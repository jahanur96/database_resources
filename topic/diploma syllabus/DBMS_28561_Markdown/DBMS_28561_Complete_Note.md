```sql
DROP DATABASE IF EXISTS polytechnic_db;
CREATE DATABASE polytechnic_db CHARACTER SET utf8mb4;
USE polytechnic_db;

CREATE TABLE department (
    dept_id    INT PRIMARY KEY,
    dept_name  VARCHAR(40) NOT NULL UNIQUE,
    building   VARCHAR(20)
);

CREATE TABLE student (
    roll       INT PRIMARY KEY,
    name       VARCHAR(40) NOT NULL,
    dept_id    INT,
    semester   TINYINT CHECK (semester BETWEEN 1 AND 8),
    cgpa       DECIMAL(3,2),
    city       VARCHAR(30),

    FOREIGN KEY (dept_id) REFERENCES department(dept_id)
);

    teacher_id INT PRIMARY KEY,
    name       VARCHAR(40) NOT NULL,
    dept_id    INT,
    salary     INT,
    join_date  DATE,
    FOREIGN KEY (dept_id) REFERENCES department(dept_id)
);

CREATE TABLE course (
    course_code VARCHAR(10) PRIMARY KEY,
    title       VARCHAR(40) NOT NULL,
    credit      TINYINT,
    dept_id     INT,
    FOREIGN KEY (dept_id) REFERENCES department(dept_id)
);

CREATE TABLE enrollment (
    roll        INT,
    course_code VARCHAR(10),
    marks       INT,
    PRIMARY KEY (roll, course_code),
    FOREIGN KEY (roll) REFERENCES student(roll),
    FOREIGN KEY (course_code) REFERENCES course(course_code)
);

CREATE TABLE account (
    acc_no   INT PRIMARY KEY,
    holder   VARCHAR(40),
    balance  INT CHECK (balance >= 0)
);
```

# অধ্যায় ১: ডাটাবেস সিস্টেমের প্রাথমিক ধারণা

> **এক নজরে:** Data, Information, Database, DBMS কী; প্রচলিত File Processing System-এর সমস্যা; DBMS-এর উদ্দেশ্য, বৈশিষ্ট্য, সুবিধা ও অসুবিধা; Data Abstraction-এর তিনটি স্তর; Schema ও Instance; Data Independence; DBMS-এর ব্যবহারক্ষেত্র।

## Data, Information, Field, Record, File

**Data (ডাটা/উপাত্ত):** প্রক্রিয়াকরণ করা হয়নি এমন কাঁচা তথ্য, যেমন সংখ্যা, অক্ষর, ছবি বা শব্দ, যার আলাদাভাবে তেমন অর্থ নেই। যেমন: `101`, `Rahim`, `3.75`।

**Information (তথ্য):** Data প্রক্রিয়াকরণ করে যে অর্থপূর্ণ ফল পাওয়া যায়। যেমন: "রোল 101-এর Rahim-এর CGPA 3.75, সে বিভাগে দ্বিতীয়।"

> **সহজ উদাহরণ:** বাজারের ফর্দে লেখা "চাল 5, ডাল 2, তেল 1" হলো Data। "এ মাসে বাজার খরচ 1200 টাকা, গত মাসের চেয়ে 10% বেশি" হলো Information।

| Data | Information |
|---|---|
| কাঁচা, অপ্রক্রিয়াজাত | প্রক্রিয়াজাত, অর্থপূর্ণ |
| একা তেমন অর্থ বহন করে না | সিদ্ধান্ত নিতে সাহায্য করে |
| Input | Output |
| যেমন: 82, 75, 88 | যেমন: গড় নম্বর 81.67 |

**Field (ফিল্ড):** একটি নির্দিষ্ট ধরনের Data রাখার ঘর, যেমন `roll`, `name`, `cgpa`। Table-এ এটাই **Column** বা **Attribute**।

**Record (রেকর্ড):** একটি বস্তু বা ব্যক্তির সব Field-এর মান একসঙ্গে। Table-এ এটাই একটি **Row** বা **Tuple**। যেমন: `(101, Rahim, 1, 6, 3.75, Dhaka, ...)`।

**File (ফাইল):** একই ধরনের অনেকগুলো Record-এর সংগ্রহ। যেমন সব ছাত্রের Record মিলে Student File।

**Metadata (মেটাডাটা):** **Data সম্পর্কে Data।** যেমন `roll` Field-টি INT ধরনের, Primary Key; `name` সর্বোচ্চ 40 অক্ষর। DBMS এগুলো **Data Dictionary**-তে রাখে।

## Database ও Database Management System (DBMS)

**Database (ডাটাবেস):** **পরস্পর সম্পর্কযুক্ত Data-র একটি সুসংগঠিত সংগ্রহ**, যা নির্দিষ্ট উদ্দেশ্যে সংরক্ষণ করা হয় আর সহজে খুঁজে পাওয়া, হালনাগাদ করা ও ব্যবস্থাপনা করা যায়। যেমন: একটি পলিটেকনিকের ছাত্র, শিক্ষক, বিভাগ, কোর্স ও ফলাফলের সব Data মিলে একটি Database।

**Database Management System (DBMS):** **পরস্পর সম্পর্কযুক্ত Data-র সংগ্রহ (Database) এবং সেই Data তৈরি, সংরক্ষণ, পরিবর্তন, খোঁজা ও নিয়ন্ত্রণ করার জন্য একগুচ্ছ প্রোগ্রাম (Software)।**

সহজ ভাষায়: DBMS = Database + Database চালানোর Software।

**জনপ্রিয় DBMS:** MySQL, Oracle, Microsoft SQL Server, PostgreSQL, SQLite, IBM DB2, MariaDB, Microsoft Access।

> **উদাহরণ:** লাইব্রেরির বইগুলো হলো Database। লাইব্রেরিয়ান, যিনি বই সাজান, খুঁজে দেন, কে কোন বই নিল তার হিসাব রাখেন আর অনুমতি ছাড়া কাউকে বই দেন না, তিনি হলেন DBMS।

## প্রচলিত File Processing System ও এর সমস্যা

Database আসার আগে প্রতিটি বিভাগ নিজের আলাদা File আর আলাদা Program ব্যবহার করত। একে **Conventional File Processing System** বলে।

![File Processing System বনাম Database Approach](images/file_vs_db.png){width=6in}

**উদাহরণ:** ভর্তি শাখা `student.txt`-এ ছাত্রের নাম-ঠিকানা রাখে। পরীক্ষা শাখা `result.txt`-এ আবার নাম রাখে। হিসাব শাখা `fees.txt`-এ আবার নাম রাখে। একই তথ্য তিন জায়গায়!

**File Processing System-এর সমস্যাগুলো (পরীক্ষায় খুব গুরুত্বপূর্ণ):**

1. **Data Redundancy (ডাটার পুনরাবৃত্তি):** একই Data একাধিক File-এ বারবার থাকে। এতে জায়গা নষ্ট হয়।
2. **Data Inconsistency (অসামঞ্জস্যতা):** এক File-এ ঠিকানা বদলানো হলো, অন্যটিতে হলো না। এখন কোনটা সঠিক, বোঝা যায় না।
3. **Difficulty in Accessing Data:** নতুন প্রশ্নের উত্তর পেতে ("ঢাকার যেসব ছাত্রের CGPA 3.5-এর বেশি") প্রতিবার নতুন Program লিখতে হয়।
4. **Data Isolation:** Data বিভিন্ন File-এ, বিভিন্ন Format-এ ছড়ানো থাকে, তাই একসঙ্গে আনা কঠিন।
5. **Integrity Problem:** "CGPA 4.00-এর বেশি হতে পারবে না" ধরনের নিয়ম প্রতিটি Program-এর ভেতরে আলাদাভাবে লিখতে হয়। নিয়ম বদলালে সব Program বদলাতে হয়।
6. **Atomicity Problem:** টাকা পাঠানোর মাঝপথে বিদ্যুৎ চলে গেলে এক Account থেকে টাকা কাটা হলো, কিন্তু অন্যটিতে যোগ হলো না। "হয় পুরোটা, না হয় কিছুই না" নিশ্চিত করা যায় না।
7. **Concurrent Access Anomaly:** দুজন একসঙ্গে একই Data বদলালে ভুল ফল আসে।
8. **Security Problem:** কে কোন Data দেখতে পারবে, তা নিয়ন্ত্রণ করা কঠিন।

## DBMS-এর উদ্দেশ্য (Purpose)

উপরের সমস্যাগুলো দূর করাই DBMS-এর মূল উদ্দেশ্য:

1. Data Redundancy ও Inconsistency কমানো।
2. সহজে Data খোঁজা ও ব্যবহার করা (Query Language দিয়ে)।
3. Data Isolation দূর করে সব Data এক জায়গায় সমন্বিত করা।
4. Integrity Constraint (নিয়ম) কেন্দ্রীয়ভাবে প্রয়োগ করা।
5. Atomicity নিশ্চিত করা (Transaction)।
6. একাধিক ব্যবহারকারীকে নিরাপদে একসঙ্গে কাজ করতে দেওয়া (Concurrency Control)।
7. Data-র নিরাপত্তা (Security) নিশ্চিত করা।
8. Backup ও Recovery-র ব্যবস্থা করা।

## DBMS বনাম File Processing System

| বিষয় | File Processing System | DBMS |
|---|---|---|
| Data Redundancy | বেশি | কম (নিয়ন্ত্রিত) |
| Data Consistency | নিশ্চিত নয় | নিশ্চিত |
| Data খোঁজা | প্রতিবার নতুন Program লাগে | Query (SQL) দিয়ে সহজে |
| Data Sharing | কঠিন | সহজ |
| Security | দুর্বল | শক্তিশালী (User, Permission) |
| Integrity | Program-এর ভেতরে | কেন্দ্রীয়ভাবে Constraint |
| Concurrency | সমস্যা হয় | Concurrency Control আছে |
| Backup & Recovery | নিজে করতে হয় | স্বয়ংক্রিয় ব্যবস্থা |
| Data Independence | নেই | আছে |
| খরচ | কম | বেশি (Software, Hardware, দক্ষ লোক) |
| উদাহরণ | .txt, .csv ফাইল | MySQL, Oracle |

## DBMS-এর বৈশিষ্ট্য, সুবিধা ও অসুবিধা

**বৈশিষ্ট্য (Characteristics):**

- বাস্তব জগতের Entity (ছাত্র, শিক্ষক) আর তাদের সম্পর্ক উপস্থাপন করে।
- Data আর Program আলাদা থাকে (Data Independence)।
- Data Dictionary-তে Metadata রাখে (Self-describing)।
- একাধিক View দেয়: ছাত্র শুধু নিজের ফল দেখে, হিসাবরক্ষক শুধু ফি দেখেন।
- Multi-user ও Concurrent Access সমর্থন করে।
- Query Language (SQL) দেয়।
- ACID বৈশিষ্ট্যসহ Transaction সমর্থন করে।

**সুবিধা (Advantages):**

1. Redundancy নিয়ন্ত্রণ।
2. Data Consistency।
3. Data Sharing।
4. Data Integrity।
5. Data Security।
6. Backup ও Recovery।
7. দ্রুত ও সহজ Query।
8. Standard প্রয়োগ (একই নিয়মে সব Data)।
9. Application তৈরিতে কম সময় লাগে।

**অসুবিধা (Disadvantages):**

1. খরচ বেশি (Software License, শক্তিশালী Hardware)।
2. জটিল। চালাতে দক্ষ লোক (DBA) লাগে।
3. Database বড় হলে বেশি জায়গা আর Memory লাগে।
4. কেন্দ্রীয় Database নষ্ট হলে সব Application বন্ধ হয়ে যায় (Single point of failure)।
5. ছোট, সাধারণ কাজের জন্য File System-এর চেয়ে ধীর হতে পারে।

## Data Abstraction (ডাটা অ্যাবস্ট্রাকশন)

**Data Abstraction:** **ব্যবহারকারীর কাছ থেকে Data সংরক্ষণের জটিল খুঁটিনাটি লুকিয়ে রেখে শুধু প্রয়োজনীয় অংশ দেখানোর প্রক্রিয়া।**

> **উদাহরণ:** গাড়ি চালাতে আপনাকে Engine-এর ভেতরের কাজ জানতে হয় না। Steering, Brake আর Accelerator জানলেই চলে। DBMS-ও ব্যবহারকারীকে শুধু Table দেখায়, Disk-এর Block-Sector নয়।

![Data Abstraction-এর তিনটি স্তর](images/three_level.png){width=5in}

**তিনটি স্তর (Three Levels of Abstraction):**

1. **Physical Level (Internal Level):** সবচেয়ে নিচের স্তর। Data **কীভাবে (How)** Disk-এ সংরক্ষিত, যেমন Block, Index, File Structure। শুধু DBMS আর DBA জানেন।
2. **Logical Level (Conceptual Level):** **কী (What)** Data আছে আর তাদের মধ্যে সম্পর্ক কী, যেমন `student(roll, name, dept_id, ...)`। DBA আর Programmer এই স্তরে কাজ করেন।
3. **View Level (External Level):** সবচেয়ে ওপরের স্তর। প্রত্যেক ব্যবহারকারী Database-এর শুধু তাঁর দরকারি অংশ দেখেন। একই Database-এর অনেক View থাকতে পারে।

এই তিন স্তরের কাঠামোকে **ANSI/SPARC Three-Schema Architecture**-ও বলে।

## Schema ও Instance

**Schema (স্কিমা):** **Database-এর সামগ্রিক নকশা বা কাঠামো।** কোন Table, কোন Column, কোন Data Type, কোন Key। Schema সাধারণত খুব কম বদলায়।

**Instance (ইনস্ট্যান্স):** **কোনো নির্দিষ্ট মুহূর্তে Database-এ সংরক্ষিত Data-র সংগ্রহ।** নতুন ছাত্র ভর্তি হলে Instance বদলায়, Schema নয়।

> **উদাহরণ:** একটি বাড়ির নকশা (Blueprint) হলো Schema। কোনো এক দিন বাড়িতে কে কে আছে, কোন ঘরে কী আসবাব, তা হলো Instance।

| Schema | Instance |
|---|---|
| Database-এর কাঠামো (নকশা) | নির্দিষ্ট সময়ের Data |
| খুব কম পরিবর্তন হয় | প্রতিনিয়ত পরিবর্তন হয় |
| DDL দিয়ে তৈরি | DML দিয়ে পরিবর্তন |
| Programming-এর Variable Declaration-এর মতো | Variable-এর মানের মতো |

**Schema-র প্রকারভেদ:**

1. **Physical Schema:** Physical Level-এর নকশা (Storage Structure)।
2. **Logical Schema:** Logical Level-এর নকশা (Table ও সম্পর্ক)।
3. **Sub-schema (External/View Schema):** View Level-এর নকশা। একেকজন ব্যবহারকারীর জন্য একেকটি।

## Data Independence (ডাটা ইন্ডিপেন্ডেন্স)

**Data Independence:** **এক স্তরের Schema পরিবর্তন করলেও তার ওপরের স্তরের Schema বা Application Program পরিবর্তন করতে হয় না**, এমন ক্ষমতা।

1. **Physical Data Independence:** Physical Schema বদলালেও (যেমন নতুন Index, নতুন Disk) Logical Schema আর Application অপরিবর্তিত থাকে। এটা **অর্জন করা সহজ**।
2. **Logical Data Independence:** Logical Schema বদলালেও (যেমন নতুন Column যোগ) View আর Application অপরিবর্তিত থাকে। এটা **অর্জন করা কঠিন**।

## DBMS-এর ব্যবহারক্ষেত্র (Applications)

| ক্ষেত্র | কী কাজে লাগে |
|---|---|
| ব্যাংক | Account, লেনদেন, ঋণ (যেমন bKash, ব্যাংক) |
| শিক্ষাপ্রতিষ্ঠান | ভর্তি, ফলাফল, উপস্থিতি (BTEB Result) |
| রেলওয়ে/এয়ারলাইন | টিকিট বুকিং, সময়সূচি |
| হাসপাতাল | রোগীর তথ্য, প্রেসক্রিপশন |
| E-commerce | পণ্য, অর্ডার, Customer (Daraz) |
| সরকার | NID, পাসপোর্ট, ভূমি রেকর্ড |
| টেলিকম | কল রেকর্ড, বিলিং |
| সোশ্যাল মিডিয়া | প্রোফাইল, পোস্ট, বন্ধু তালিকা |

## Data Integrity, Redundancy ও Inconsistency (সংক্ষেপে)

- **Data Integrity:** Database-এর Data-র **নির্ভুলতা ও সামঞ্জস্যতা** বজায় রাখা। যেমন CGPA 0 থেকে 4-এর মধ্যে, রোল নম্বর অনন্য।
- **Data Redundancy:** একই Data একাধিক জায়গায় অপ্রয়োজনীয়ভাবে সংরক্ষণ।
- **Data Inconsistency:** একই Data-র বিভিন্ন কপিতে বিভিন্ন মান থাকা। এটা Redundancy-র ফল।

## মনে রাখার টিপস

- **Physical = How, Logical = What, View = Who sees what।**
- File System-এর ৮টি সমস্যা মনে রাখার ছড়া: **"RIDIIACS"**: Redundancy, Inconsistency, Difficulty in access, Isolation, Integrity, Atomicity, Concurrency, Security।
- Schema = নকশা (কম বদলায়), Instance = বর্তমান Data (সবসময় বদলায়)।

**অতিসংক্ষিপ্ত প্রশ্ন ও উত্তর**

1. **Data কী?** প্রক্রিয়াকরণ না করা কাঁচা তথ্য, যেমন সংখ্যা, অক্ষর বা ছবি।
2. **Database কী?** পরস্পর সম্পর্কযুক্ত Data-র সুসংগঠিত সংগ্রহ।
3. **DBMS কী?** Database তৈরি, সংরক্ষণ, পরিবর্তন ও নিয়ন্ত্রণের Software; যেমন MySQL, Oracle।
4. **Metadata কী?** Data সম্পর্কে Data, যেমন Column-এর নাম, Type, দৈর্ঘ্য।
5. **Data Redundancy কী?** একই Data-র অপ্রয়োজনীয় পুনরাবৃত্তি।
6. **Data Inconsistency কী?** একই Data-র বিভিন্ন কপিতে ভিন্ন ভিন্ন মান।
7. **Field কী?** একটি নির্দিষ্ট ধরনের Data রাখার ঘর (Column)।
8. **Database Integrity কী?** Data-র নির্ভুলতা ও সামঞ্জস্যতা।
9. **Schema কয় প্রকার?** তিন প্রকার: Physical, Logical ও Sub-schema (View)।
10. **Instance কী?** নির্দিষ্ট মুহূর্তে Database-এ থাকা Data।
11. **Data Abstraction-এর স্তর কয়টি?** তিনটি: Physical, Logical ও View।
12. **কোন Data Independence অর্জন করা কঠিন?** Logical Data Independence।

**সংক্ষিপ্ত ও রচনামূলক প্রশ্ন (উত্তর এই অধ্যায়ের সংশ্লিষ্ট অংশে)**

1. DBMS-এর সুবিধা ও অসুবিধা লেখ।
2. DBMS-এর উদ্দেশ্যসমূহ বর্ণনা কর।
3. DBMS ও প্রচলিত File Processing System-এর পার্থক্য লেখ।
4. চিত্রসহ প্রচলিত File Processing System এবং DBMS-এর তুলনামূলক বর্ণনা কর।
5. File Processing System-এর অসুবিধাগুলো বর্ণনা কর।
6. Data Abstraction-এর তিনটি স্তর চিত্রসহ ব্যাখ্যা কর।
7. Schema ও Instance-এর পার্থক্য লেখ।
8. Data Independence কী? এর প্রকারভেদ লেখ।


# অধ্যায় ২: ডাটাবেসের ভাষা, ব্যবহারকারী, ম্যানেজার ও অ্যাডমিনিস্ট্রেটর

> **এক নজরে:** Database Language (DDL, DML, DCL, TCL); Procedural ও Non-procedural DML; Data Dictionary; DROP, DELETE ও TRUNCATE-এর পার্থক্য; Database User-এর প্রকারভেদ; Database Manager (Storage Manager) ও Query Processor; Database Administrator (DBA)-এর কাজ; DBMS-এর সামগ্রিক কাঠামো।

**আগের অধ্যায়ের সঙ্গে সম্পর্ক:** অধ্যায় ১-এ দেখেছেন DBMS কী আর কেন দরকার। এবার দেখব DBMS-এর সঙ্গে কোন "ভাষায়" কথা বলতে হয়, কারা কথা বলে, আর DBMS-এর ভেতরে কোন অংশ কী কাজ করে।

## Database Language (ডাটাবেস ভাষা)

DBMS-কে নির্দেশ দেওয়ার ভাষা মূলত **SQL (Structured Query Language)**। কাজ অনুযায়ী SQL Command-গুলোকে চার ভাগে ভাগ করা হয়:

| ভাষা | পূর্ণরূপ | কাজ | Command |
|---|---|---|---|
| **DDL** | Data Definition Language | Database-এর **কাঠামো (Schema)** তৈরি ও পরিবর্তন | CREATE, ALTER, DROP, TRUNCATE, RENAME |
| **DML** | Data Manipulation Language | **Data** যোগ, পরিবর্তন, মোছা ও খোঁজা | SELECT, INSERT, UPDATE, DELETE |
| **DCL** | Data Control Language | **অনুমতি (Permission)** দেওয়া ও নেওয়া | GRANT, REVOKE |
| **TCL** | Transaction Control Language | **Transaction** নিয়ন্ত্রণ | COMMIT, ROLLBACK, SAVEPOINT |

### DDL (Data Definition Language)

**DDL:** **যে ভাষা দিয়ে Database Schema, অর্থাৎ Table, Column, Constraint, Index, View ইত্যাদির কাঠামো সংজ্ঞায়িত ও পরিবর্তন করা হয়।** DDL-এর ফলাফল **Data Dictionary**-তে জমা থাকে।

```sql
CREATE TABLE notice (
    notice_id  INT PRIMARY KEY,
    title      VARCHAR(60) NOT NULL,
    publish_on DATE
);
```

```sql
ALTER TABLE notice ADD COLUMN dept_id INT;
```

### DML (Data Manipulation Language)

**DML:** **যে ভাষা দিয়ে Database-এর Data খোঁজা (Retrieve), যোগ (Insert), পরিবর্তন (Update) ও মোছা (Delete) হয়।**

**DML-এর চারটি মৌলিক Operation:**

1. **Retrieval:** Data খোঁজা (`SELECT`)
2. **Insertion:** নতুন Data যোগ (`INSERT`)
3. **Deletion:** Data মোছা (`DELETE`)
4. **Modification:** Data পরিবর্তন (`UPDATE`)

```sql
INSERT INTO notice VALUES
(1, 'Mid-term exam routine', '2026-03-01', 1),
(2, 'Lab report submission', '2026-03-05', 1),
(3, 'Holiday notice',        '2026-03-10', NULL);

UPDATE notice SET title = 'Mid-term exam routine (revised)' WHERE notice_id = 1;

SELECT * FROM notice;
```

**Output:**

| notice_id | title | publish_on | dept_id |
|---|---|---|---|
| 1 | Mid-term exam routine (revised) | 2026-03-01 | 1 |
| 2 | Lab report submission | 2026-03-05 | 1 |
| 3 | Holiday notice | 2026-03-10 | NULL |

_(মোট 3টি row)_

**DML দুই প্রকার:**

| Procedural DML | Non-procedural (Declarative) DML |
|---|---|
| ব্যবহারকারী বলে দেয় **কী Data** লাগবে **এবং কীভাবে (How)** আনতে হবে | শুধু বলে **কী Data (What)** লাগবে। কীভাবে আনবে, DBMS ঠিক করে |
| শেখা ও লেখা কঠিন | শেখা সহজ |
| যেমন: Relational Algebra, PL/SQL Loop | যেমন: SQL-এর SELECT |

### DCL ও TCL

```text
GRANT SELECT ON polytechnic_db.student TO 'office_user'@'localhost';   -- DCL
REVOKE SELECT ON polytechnic_db.student FROM 'office_user'@'localhost'; -- DCL
COMMIT;      -- TCL: পরিবর্তন স্থায়ী করা
ROLLBACK;    -- TCL: পরিবর্তন বাতিল করা
```

এগুলোর বিস্তারিত অধ্যায় ৬ (Security) আর অধ্যায় ৯ (Transaction)-এ দেখবেন।

### DDL ও DML-এর পার্থক্য

| DDL | DML |
|---|---|
| Database-এর **কাঠামো** নিয়ে কাজ করে | Database-এর **Data** নিয়ে কাজ করে |
| CREATE, ALTER, DROP, TRUNCATE | SELECT, INSERT, UPDATE, DELETE |
| Schema পরিবর্তন করে | Instance পরিবর্তন করে |
| সাধারণত Auto-commit হয় (ROLLBACK হয় না) | ROLLBACK করা যায় |
| মূলত DBA/Developer ব্যবহার করেন | সাধারণ ব্যবহারকারীও (Application-এর মাধ্যমে) |

## DROP, DELETE ও TRUNCATE-এর পার্থক্য

তিনটিই "মোছা"র কাজ করে, কিন্তু আলাদাভাবে। নিচে একটি ছোট পরীক্ষা:

```sql
CREATE TABLE temp_log (id INT, msg VARCHAR(20));
INSERT INTO temp_log VALUES (1, 'a'), (2, 'b'), (3, 'c');

DELETE FROM temp_log WHERE id = 2;      -- শুধু id 2 মুছবে
```

```sql
SELECT COUNT(*) AS rows_after_delete FROM temp_log;
```

**Output:**

| rows_after_delete |
|---|
| 2 |

_(মোট 1টি row)_

```sql
TRUNCATE TABLE temp_log;                -- সব row মুছবে, Table থাকবে
```

```sql
SELECT COUNT(*) AS rows_after_truncate FROM temp_log;
```

**Output:**

| rows_after_truncate |
|---|
| 0 |

_(মোট 1টি row)_

```sql
DROP TABLE temp_log;                    -- Table-টাই মুছে যাবে
```

```sql
SELECT COUNT(*) AS rows_after_drop FROM temp_log;
```

**MySQL Error:**

```text
ERROR 1146 (42S02): Table 'polytechnic_db.temp_log' doesn't exist
```

DROP-এর পরে Table-টাই আর নেই, তাই Error আসে।

| বিষয় | DELETE | TRUNCATE | DROP |
|---|---|---|---|
| ভাষা | DML | DDL | DDL |
| কী মোছে | নির্দিষ্ট বা সব **row** | **সব row** | **পুরো Table** (কাঠামোসহ) |
| WHERE ব্যবহার | করা যায় | করা যায় না | করা যায় না |
| Table-এর কাঠামো | থাকে | থাকে | থাকে না |
| ROLLBACK | করা যায় (Transaction-এর ভেতরে) | সাধারণত করা যায় না | করা যায় না |
| গতি | ধীর (row ধরে ধরে) | দ্রুত | দ্রুত |
| Trigger চালু হয় | হ্যাঁ | না | না |

> **মনে রাখুন:** DELETE = বইয়ের কিছু পাতা ছিঁড়ে ফেলা; TRUNCATE = সব পাতা ছিঁড়ে ফেলা, মলাট থাকে; DROP = পুরো বইটাই ফেলে দেওয়া।

## Data Dictionary (ডাটা ডিকশনারি)

**Data Dictionary:** **Database সম্পর্কে Metadata সংরক্ষণের একটি বিশেষ ভান্ডার (Catalog)।** এতে থাকে: Table ও Column-এর নাম, Data Type, Constraint, Index, User ও তাদের Permission, View-এর সংজ্ঞা।

**প্রয়োজনীয়তা:**

- DBMS প্রতিটি Query চালানোর আগে Data Dictionary দেখে যাচাই করে Table/Column আছে কিনা।
- DBA Database-এর পুরো কাঠামো এক জায়গায় দেখতে পান।
- Security: কে কী করতে পারবে, তা এখানে থাকে।
- Documentation হিসেবে কাজ করে।

MySQL-এ Data Dictionary দেখা যায় `INFORMATION_SCHEMA` দিয়ে:

```sql
SELECT COLUMN_NAME, DATA_TYPE, IS_NULLABLE, COLUMN_KEY
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = 'polytechnic_db' AND TABLE_NAME = 'student'
ORDER BY ORDINAL_POSITION;
```

**Output:**

| COLUMN_NAME | DATA_TYPE | IS_NULLABLE | COLUMN_KEY |
|---|---|---|---|
| roll | int | NO | PRI |
| name | varchar | NO |  |
| dept_id | int | YES | MUL |
| semester | tinyint | YES |  |
| cgpa | decimal | YES |  |
| city | varchar | YES |  |
| phone | varchar | YES |  |

_(মোট 7টি row)_

## Database User (ব্যবহারকারী)-এর প্রকারভেদ

1. **Naive User (সাধারণ ব্যবহারকারী):** DBMS সম্পর্কে কিছু না জেনেই তৈরি করা Application ব্যবহার করেন। যেমন: ATM থেকে টাকা তোলা ব্যক্তি, অনলাইনে রেজাল্ট দেখা ছাত্র।
2. **Application Programmer:** Java, PHP, Python ইত্যাদি দিয়ে Database ব্যবহারকারী Software তৈরি করেন। যেমন: পলিটেকনিকের Result Management Software-এর Developer।
3. **Sophisticated User:** Program না লিখে সরাসরি SQL Query বা Analysis Tool ব্যবহার করেন। যেমন: Data Analyst, প্রকৌশলী, বিজ্ঞানী।
4. **Specialized User:** বিশেষ ধরনের জটিল Database Application লেখেন, যেমন CAD, Expert System, ছবি/শব্দের Database।
5. **Database Administrator (DBA):** পুরো Database System-এর কেন্দ্রীয় নিয়ন্ত্রক (নিচে বিস্তারিত)।

## Database Manager ও DBMS-এর সামগ্রিক কাঠামো

![DBMS-এর সামগ্রিক কাঠামো (Overall System Structure)](images/dbms_structure.png){width=5.6in}

DBMS-এর প্রধান দুটি অংশ: **Query Processor** আর **Storage Manager (Database Manager)**।

### Query Processor

1. **DDL Interpreter:** DDL Statement বুঝে Data Dictionary-তে সংজ্ঞা লেখে।
2. **DML Compiler:** DML Query-কে নিম্নস্তরের নির্দেশে (Evaluation Plan) রূপান্তর করে। একাধিক পদ্ধতির মধ্যে সবচেয়ে দ্রুতটি বেছে নেয়। একে **Query Optimization** বলে।
3. **Query Evaluation Engine:** DML Compiler-এর তৈরি নির্দেশগুলো আসলে চালায়।

### Database Manager (Storage Manager)

**Database Manager:** **DBMS-এর যে অংশ Disk-এ সংরক্ষিত নিম্নস্তরের Data আর Application/Query-র মধ্যে সংযোগ (Interface) হিসেবে কাজ করে।**

**উপাদান ও কাজ:**

1. **Authorization & Integrity Manager:** ব্যবহারকারীর অনুমতি আর Integrity Constraint যাচাই করে।
2. **Transaction Manager:** System failure হলেও Database সঠিক অবস্থায় রাখে, আর একসঙ্গে চলা Transaction-গুলোকে সংঘাতমুক্ত রাখে।
3. **File Manager:** Disk-এ জায়গা বরাদ্দ আর Data Structure ব্যবস্থাপনা করে।
4. **Buffer Manager:** Disk থেকে Data Main Memory-তে আনা আর কোন Data Memory-তে রাখা হবে, তা ঠিক করে।

**Database Manager-এর কাজগুলো (পরীক্ষার জন্য):**

1. **File Manager-এর সঙ্গে যোগাযোগ:** Disk-এর Data পড়া ও লেখা।
2. **Integrity Enforcement:** নিয়ম (Constraint) মানা হচ্ছে কিনা দেখা।
3. **Security Enforcement:** অনুমতি ছাড়া কেউ যেন Data দেখতে না পারে।
4. **Backup ও Recovery:** ক্ষতির পর Database আগের সঠিক অবস্থায় ফেরানো।
5. **Concurrency Control:** একসঙ্গে অনেক ব্যবহারকারীর কাজে সংঘাত এড়ানো।

### Disk-এ যা থাকে

- **Data Files:** Database-এর আসল Data।
- **Data Dictionary:** Metadata।
- **Indices:** দ্রুত খোঁজার জন্য Index।
- **Statistical Data:** Query Optimization-এর জন্য পরিসংখ্যান।

## Database Administrator (DBA)

**DBA:** **যে ব্যক্তি (বা দল) Database System-এর ওপর কেন্দ্রীয় নিয়ন্ত্রণ রাখেন এবং Data ও Program উভয়ের ব্যবস্থাপনার দায়িত্বে থাকেন।**

**DBA-এর কাজ:**

1. **Schema Definition:** DDL দিয়ে Database-এর মূল কাঠামো তৈরি করা।
2. **Storage Structure ও Access Method নির্ধারণ:** Data কোথায়, কীভাবে রাখা হবে।
3. **Schema ও Physical Organization পরিবর্তন:** প্রয়োজন অনুযায়ী কাঠামো বদলানো।
4. **Authorization প্রদান:** কে কোন Data দেখতে বা বদলাতে পারবে (GRANT/REVOKE)।
5. **Integrity Constraint নির্ধারণ।**
6. **নিয়মিত Backup নেওয়া** ও প্রয়োজনে Recovery করা।
7. **Performance Monitoring ও Tuning:** ধীর Query খুঁজে ঠিক করা, Index যোগ করা।
8. **Disk Space ব্যবস্থাপনা** ও প্রয়োজনে Upgrade।
9. **নতুন Software/Version ইনস্টল ও Update।**

> **Database Manager বনাম DBA:** Database Manager হলো DBMS-এর একটি **Software অংশ**। DBA হলেন একজন **মানুষ**, যিনি পুরো System পরিচালনা করেন।

## Database Updating ও Object (সংক্ষেপে)

- **Database Updating:** Database-এর Data-য় পরিবর্তন আনা, অর্থাৎ INSERT, UPDATE ও DELETE।
- **Object:** Database-এ সংরক্ষিত যেকোনো সংজ্ঞায়িত বস্তু, যেমন Table, View, Index, Procedure, Trigger।

```sql
DROP TABLE notice;
```

## মনে রাখার টিপস

- **DDL = Design (কাঠামো), DML = Data (তথ্য), DCL = Control (অনুমতি), TCL = Transaction।**
- Query Processor "বোঝে", Storage Manager "রাখে"।
- DBA মানুষ, Database Manager Software।

## অধ্যায় ২: প্রশ্নোত্তর

**অতিসংক্ষিপ্ত প্রশ্ন ও উত্তর**

1. **DDL কী?** Database-এর কাঠামো (Schema) সংজ্ঞায়িত করার ভাষা; যেমন CREATE, ALTER, DROP।
2. **DML-এর মৌলিক Operation কী কী?** Retrieval (SELECT), Insertion (INSERT), Deletion (DELETE), Modification (UPDATE)।
3. **DML কত প্রকার?** দুই প্রকার: Procedural ও Non-procedural।
4. **Database Administrator কে?** যিনি Database System-এর ওপর কেন্দ্রীয় নিয়ন্ত্রণ রাখেন।
5. **Database User কত প্রকার?** Naive, Application Programmer, Sophisticated, Specialized ও DBA।
6. **Data Dictionary কী?** Metadata সংরক্ষণের ভান্ডার।
7. **Database Updating কী?** INSERT, UPDATE বা DELETE দিয়ে Data পরিবর্তন।
8. **Object কী?** Database-এ সংজ্ঞায়িত বস্তু, যেমন Table, View, Index।
9. **Buffer Manager-এর কাজ কী?** Disk থেকে Data Memory-তে আনা ও Memory ব্যবস্থাপনা।
10. **TRUNCATE কোন ভাষার অংশ?** DDL।

**সংক্ষিপ্ত ও রচনামূলক প্রশ্ন**

1. DDL ও DML-এর পার্থক্য লেখ।
2. Procedural ও Non-procedural DML-এর পার্থক্য লেখ।
3. DROP, DELETE ও TRUNCATE-এর পার্থক্য লেখ।
4. Data Dictionary-র প্রয়োজনীয়তা লেখ।
5. বিভিন্ন প্রকার Database User-এর বর্ণনা দাও।
6. Database Manager-এর কাজ বর্ণনা কর।
7. Database Administrator-এর কাজ বর্ণনা কর।
8. চিত্রসহ DBMS-এর সামগ্রিক কাঠামো (Overall Structure) ব্যাখ্যা কর।


# অধ্যায় ৩: ডাটা মডেল

> **এক নজরে:** Data Model কী ও কত প্রকার; E-R Model: Entity, Attribute, Relationship; Attribute-এর প্রকারভেদ; Keys (Super, Candidate, Primary, Foreign ইত্যাদি); Mapping Cardinality; Participation; Strong ও Weak Entity; E-R Diagram-এর Symbol; Specialization, Generalization, Aggregation; E-R Diagram থেকে Table; Hierarchical ও Network Model।

**আগের অধ্যায়ের সঙ্গে সম্পর্ক:** অধ্যায় ১-এ দেখেছেন Logical Level-এ "কী Data আছে, সম্পর্ক কী" তা বর্ণনা করা হয়। সেই বর্ণনার পদ্ধতিই হলো Data Model।

## Data Model ও এর প্রকারভেদ

**Data Model:** **Data, Data-র মধ্যকার সম্পর্ক, Data-র অর্থ (Semantics) ও Constraint বর্ণনা করার জন্য ব্যবহৃত ধারণাগত সরঞ্জামের (Conceptual Tools) সমষ্টি।** সহজ কথায়, Database-এর নকশা আঁকার পদ্ধতি।

> **উদাহরণ:** বাড়ি বানানোর আগে স্থপতি নকশা আঁকেন। Data Model হলো Database-এর সেই নকশা আঁকার নিয়ম।

| Data Model | সংক্ষিপ্ত বর্ণনা | উদাহরণ |
|---|---|---|
| **Relational Model** | Data থাকে Table (Relation) আকারে, সারি ও কলামে | MySQL, Oracle |
| **Entity-Relationship (E-R) Model** | Entity, Attribute ও Relationship দিয়ে বাস্তব জগতের চিত্র | Database Design-এ |
| **Hierarchical Model** | Tree আকারে Parent-Child (One-to-Many) | IBM IMS, Windows Registry |
| **Network Model** | Graph আকারে, একটি Child-এর একাধিক Parent | IDMS |
| **Object-Based Model** | Object, Class, Inheritance ধারণা | Object-Relational DB |
| **Semi-structured Model** | নির্দিষ্ট কাঠামো ছাড়া, Tag/Key দিয়ে | XML, JSON (MongoDB) |

## Relational Data Model

**Relational Data Model:** **যে Data Model-এ Data এবং Data-র মধ্যকার সম্পর্ক কতগুলো Table (Relation)-এর মাধ্যমে প্রকাশ করা হয়।** প্রতিটি Table-এর আছে নির্দিষ্ট নামের Column আর অসংখ্য Row। এটি 1970 সালে **E. F. Codd** প্রস্তাব করেন। বর্তমানে সবচেয়ে বেশি ব্যবহৃত Model।

**সুবিধা:**

1. গঠন সহজ, Table আকারে হওয়ায় বোঝা সহজ।
2. SQL দিয়ে সহজে Query করা যায়।
3. Data Independence বেশি।
4. Normalization দিয়ে Redundancy কমানো যায়।
5. Key দিয়ে সম্পর্ক (Relationship) সহজে তৈরি করা যায়।
6. Security ও Integrity নিশ্চিত করা সহজ।

বিস্তারিত অধ্যায় ৪-এ।

## E-R Model: Entity, Entity Set, Attribute

**E-R Model (Entity-Relationship Model):** **বাস্তব জগতের বস্তু (Entity), তাদের বৈশিষ্ট্য (Attribute) ও তাদের মধ্যকার সম্পর্ক (Relationship)-এর মাধ্যমে Database-এর ধারণাগত নকশা তৈরির Model।** 1976 সালে **Peter Chen** এটি প্রস্তাব করেন।

**Entity:** **বাস্তব জগতের এমন কোনো বস্তু বা বিষয়, যা অন্য সবকিছু থেকে আলাদাভাবে চেনা যায়।** যেমন: ছাত্র Rahim, শিক্ষক Mr. Alam, DBMS কোর্স।

**Entity Set:** **একই ধরনের Entity-গুলোর সংগ্রহ।** যেমন: সব ছাত্র মিলে Student Entity Set।

**Attribute:** **Entity-র বৈশিষ্ট্য।** যেমন Student-এর roll, name, phone, age।

### Attribute-এর প্রকারভেদ

| প্রকার | অর্থ | উদাহরণ | E-R Symbol |
|---|---|---|---|
| **Simple** | আর ভাগ করা যায় না | roll, cgpa | Ellipse |
| **Composite** | ছোট ছোট অংশে ভাগ করা যায় | name = first_name + last_name; address = road + city | Ellipse থেকে শাখা Ellipse |
| **Single-valued** | একটিমাত্র মান | date_of_birth | Ellipse |
| **Multivalued** | একাধিক মান থাকতে পারে | phone (একজনের একাধিক ফোন) | **Double Ellipse** |
| **Derived** | অন্য Attribute থেকে হিসাব করা যায় | age (date_of_birth থেকে) | **Dashed Ellipse** |
| **Key Attribute** | প্রতিটি Entity-কে অনন্যভাবে চেনায় | roll | **নিচে দাগ (Underline)** |
| **NULL** | মান অজানা বা প্রযোজ্য নয় | Nila-র phone | — |

## Relationship ও Relationship Set

**Relationship:** **একাধিক Entity-র মধ্যকার সংযোগ বা সম্পর্ক।** যেমন: Rahim **enrolls in** DBMS।

**Relationship Set:** একই ধরনের Relationship-গুলোর সংগ্রহ। যেমন সব ছাত্রের সব কোর্সে ভর্তি মিলে "Enrolls" Relationship Set।

**Degree of Relationship:** Relationship-এ কতগুলো Entity Set অংশ নিচ্ছে।

- **Unary (Recursive):** একটি Entity Set নিজের সঙ্গে। যেমন: Employee **manages** Employee।
- **Binary:** দুটি Entity Set। যেমন: Student **enrolls** Course। (সবচেয়ে বেশি প্রচলিত)
- **Ternary:** তিনটি Entity Set। যেমন: Teacher **teaches** Course **in** Room।

**Relationship-এরও Attribute থাকতে পারে।** যেমন Enrolls-এর `marks`: নম্বর ছাত্রেরও না, কোর্সেরও না, বরং "এই ছাত্র এই কোর্সে" সম্পর্কের।

## Keys (কী)

Key হলো এক বা একাধিক Attribute, যা দিয়ে একটি Table-এর প্রতিটি Row-কে আলাদাভাবে চেনা যায়। ধরুন `student(roll, name, phone, nid, dept_id)`:

| Key | সংজ্ঞা | উদাহরণ |
|---|---|---|
| **Super Key** | এক বা একাধিক Attribute-এর যেকোনো সেট, যা Row-কে অনন্যভাবে চেনায় (অতিরিক্ত Attribute থাকতে পারে) | {roll}, {roll, name}, {nid}, {roll, phone} |
| **Candidate Key** | **সবচেয়ে ছোট (Minimal)** Super Key। এর কোনো অংশ বাদ দিলে আর অনন্য থাকে না | {roll}, {nid} |
| **Primary Key** | Candidate Key-গুলোর মধ্যে Database Designer যেটি বেছে নেন। **NULL হতে পারে না, Duplicate হতে পারে না** | roll |
| **Alternate Key** | যে Candidate Key-গুলো Primary Key হয়নি | nid |
| **Foreign Key** | এক Table-এর Attribute, যা অন্য Table-এর Primary Key-কে নির্দেশ করে; দুই Table-এর সম্পর্ক তৈরি করে | student.dept_id → department.dept_id |
| **Composite Key** | দুই বা ততোধিক Attribute মিলে Primary Key | enrollment(roll, course_code) |
| **Unique Key** | মান অনন্য, কিন্তু (MySQL-এ) NULL থাকতে পারে | department.dept_name |

> **মনে রাখুন:** সব Primary Key-ই Candidate Key, সব Candidate Key-ই Super Key। কিন্তু উল্টোটা সত্য নয়।
> Super Key ⊇ Candidate Key ⊇ Primary Key

## Mapping Cardinality (ম্যাপিং কার্ডিনালিটি)

**Mapping Cardinality:** **একটি Entity Set-এর একটি Entity, Relationship-এর মাধ্যমে অন্য Entity Set-এর কতগুলো Entity-র সঙ্গে যুক্ত হতে পারে, তার সংখ্যা।**

| ধরন | অর্থ | উদাহরণ |
|---|---|---|
| **One-to-One (1:1)** | A-এর একটি ↔ B-এর একটি | একজন ছাত্র ↔ একটি ID Card; একটি দেশ ↔ একজন রাষ্ট্রপতি |
| **One-to-Many (1:N)** | A-এর একটি ↔ B-এর অনেক | একটি বিভাগ ↔ অনেক ছাত্র |
| **Many-to-One (N:1)** | A-এর অনেক ↔ B-এর একটি | অনেক ছাত্র ↔ একটি বিভাগ |
| **Many-to-Many (M:N)** | A-এর অনেক ↔ B-এর অনেক | অনেক ছাত্র ↔ অনেক কোর্স |

**Participation Constraint:**

- **Total Participation:** Entity Set-এর **প্রত্যেক** Entity-কে Relationship-এ অংশ নিতেই হবে। E-R Diagram-এ **Double Line**। যেমন প্রতিটি কোর্স অবশ্যই কোনো বিভাগের।
- **Partial Participation:** কিছু Entity অংশ না-ও নিতে পারে। **Single Line**। যেমন সব শিক্ষক বিভাগীয় প্রধান নন।

## Strong Entity ও Weak Entity

**Strong Entity:** যার নিজস্ব Primary Key আছে। যেমন: Employee (emp_id)।

**Weak Entity:** **যার নিজস্ব পূর্ণ Primary Key নেই; চেনার জন্য অন্য একটি Strong Entity (Owner/Identifying Entity)-র ওপর নির্ভরশীল।** এর আংশিক Key-কে **Discriminator** (বা Partial Key) বলে।

> **উদাহরণ:** Employee-র Dependent (পরিবারের সদস্য)। দুজন ভিন্ন কর্মীর সন্তানের নাম "Rafi" হতে পারে। তাই শুধু নাম দিয়ে চেনা যায় না, (emp_id + dependent_name) লাগে। এখানে Dependent হলো Weak Entity, Employee হলো Owner, আর dependent_name হলো Discriminator।

| Strong Entity | Weak Entity |
|---|---|
| নিজস্ব Primary Key আছে | নিজস্ব পূর্ণ Primary Key নেই |
| স্বাধীনভাবে থাকতে পারে | Owner Entity ছাড়া থাকতে পারে না |
| Single Rectangle | **Double Rectangle** |
| সাধারণ Relationship: Diamond | Identifying Relationship: **Double Diamond** |
| Key-তে Solid Underline | Discriminator-এ **Dashed Underline** |
| Participation Total/Partial দুটোই হতে পারে | সবসময় **Total Participation** |

## E-R Diagram ও এর Symbol

**E-R Diagram:** **E-R Model-কে চিত্রের মাধ্যমে প্রকাশ করার পদ্ধতি**, যেখানে Entity, Attribute ও Relationship নির্দিষ্ট Symbol দিয়ে আঁকা হয়।

![E-R Diagram-এর প্রধান Symbol](images/er_symbols.png){width=6in}

| Symbol | অর্থ |
|---|---|
| Rectangle (আয়তক্ষেত্র) | Entity Set |
| Double Rectangle | Weak Entity Set |
| Diamond (রম্বস) | Relationship Set |
| Double Diamond | Identifying Relationship (Weak Entity-র সঙ্গে) |
| Ellipse (উপবৃত্ত) | Attribute |
| Ellipse, Underline সহ | Key Attribute |
| Double Ellipse | Multivalued Attribute |
| Dashed Ellipse | Derived Attribute |
| Line (রেখা) | Entity–Attribute বা Entity–Relationship সংযোগ |
| Double Line | Total Participation |
| তীর (Arrow) / 1, N, M লেখা | Cardinality |

### উদাহরণ: পলিটেকনিকের E-R Diagram

![Student–Course–Department E-R Diagram](images/er_example.png){width=6in}

**কীভাবে পড়বেন:**

- Student আর Course-এর মধ্যে **M:N** সম্পর্ক (Enrolls)। একজন ছাত্র অনেক কোর্সে, একটি কোর্সে অনেক ছাত্র।
- `marks` হলো Enrolls **Relationship**-এর Attribute।
- Student আর Department-এর মধ্যে **N:1** সম্পর্ক (Belongs To)।
- `phone` Multivalued (Double Ellipse), `age` Derived (Dashed Ellipse), `roll` Key (Underline)।

### E-R Diagram থেকে Table তৈরির নিয়ম (Reduction to Tables)

1. **প্রতিটি Strong Entity → একটি Table।** Attribute-গুলো Column হবে। Key Attribute হবে Primary Key।
2. **Composite Attribute → তার অংশগুলো আলাদা Column।**
3. **Multivalued Attribute → আলাদা Table** (Entity-র Key + মান)। যেমন `student_phone(roll, phone)`।
4. **Derived Attribute → সাধারণত Column হয় না** (Query-তে হিসাব করা হয়)।
5. **1:N Relationship → "N" পাশের Table-এ "1" পাশের Primary Key-টি Foreign Key হিসেবে।** যেমন `student.dept_id`।
6. **M:N Relationship → নতুন Table**, যার Primary Key হয় দুই পাশের Primary Key মিলে। Relationship-এর Attribute-ও থাকে। যেমন `enrollment(roll, course_code, marks)`।
7. **1:1 Relationship → যেকোনো এক পাশের Table-এ অন্য পাশের Primary Key Foreign Key হিসেবে।**
8. **Weak Entity → Table**, যার Primary Key = Owner-এর Primary Key + Discriminator।

আমাদের `polytechnic_db` ঠিক এই নিয়মে তৈরি। `enrollment` Table-টি M:N সম্পর্কের ফল।

## Specialization, Generalization ও Aggregation

![Specialization ও Generalization](images/specialization.png){width=4.5in}

**Specialization (বিশেষায়ন):** **Top-down পদ্ধতি।** একটি সাধারণ Entity Set-কে তার বিশেষ বৈশিষ্ট্য অনুযায়ী ছোট ছোট Sub-group-এ ভাগ করা। যেমন: Person → Student (cgpa আছে) ও Teacher (salary আছে)।

**Generalization (সাধারণীকরণ):** **Bottom-up পদ্ধতি।** একাধিক Entity Set-এর সাধারণ বৈশিষ্ট্যগুলো নিয়ে একটি উচ্চতর Entity Set বানানো। যেমন: Student আর Teacher দুজনেরই name, address আছে, তাই মিলে Person।

দুটোতেই **ISA ("is a") Relationship** ব্যবহৃত হয়, যা **ত্রিভুজ** দিয়ে আঁকা হয়। Student **is a** Person। নিচের স্তরের Entity ওপরের স্তরের সব Attribute পায়। একে **Attribute Inheritance** বলে।

| Specialization | Generalization |
|---|---|
| Top-down (ওপর থেকে নিচে) | Bottom-up (নিচ থেকে ওপরে) |
| একটি Entity থেকে একাধিক Sub-entity | একাধিক Entity মিলে একটি Super-entity |
| পার্থক্য খোঁজে | মিল খোঁজে |
| Entity-র সংখ্যা বাড়ে | Entity-র সংখ্যা কমে |

**Aggregation (একত্রীকরণ):** **E-R Model-এ একটি Relationship-এর সঙ্গে আরেকটি Relationship যুক্ত করা যায় না।** এই সীমাবদ্ধতা দূর করতে **একটি Relationship ও তার Entity-গুলোকে একসঙ্গে একটি উচ্চতর Entity হিসেবে ধরা হয়।** একেই Aggregation বলে।

![Aggregation](images/aggregation.png){width=5.5in}

> **উদাহরণ:** "Teacher **teaches** Course"। এখন অধ্যক্ষ (Principal) নজরদারি করবেন কোনো নির্দিষ্ট শিক্ষকের নির্দিষ্ট কোর্স পড়ানো, শুধু শিক্ষক বা শুধু কোর্স নয়। তাই (Teacher–Teaches–Course)-কে একটি বাক্সে রেখে একটি Entity ধরা হয়, তারপর সেটার সঙ্গে Principal-এর "Monitors" Relationship।

## Hierarchical Data Model

**Hierarchical Data Model:** **যে Model-এ Data একটি উল্টো গাছের (Tree) মতো সাজানো থাকে।** সবার ওপরে একটি **Root**। প্রতিটি **Child**-এর ঠিক **একটি Parent**, কিন্তু একটি Parent-এর অনেক Child থাকতে পারে (1:N)।

![Hierarchical Model](images/hierarchical.png){width=5in}

**সুবিধা:** সহজ, দ্রুত (Parent থেকে Child-এ সরাসরি যাওয়া যায়), Data-র নিরাপত্তা ও Integrity ভালো।

**অসুবিধা:** M:N সম্পর্ক প্রকাশ করা যায় না। একই Data বারবার রাখতে হয় (Redundancy)। Root ছাড়া অন্য পথে Data খোঁজা কঠিন। কাঠামো পরিবর্তন জটিল।

## Network Data Model

**Network Data Model:** **যে Model-এ Data Record আর Link (Pointer) দিয়ে একটি Graph-এর মতো সাজানো থাকে**, এবং **একটি Child-এর একাধিক Parent** থাকতে পারে। ফলে M:N সম্পর্ক প্রকাশ করা যায়। CODASYL (DBTG) এটির মান নির্ধারণ করে।

![Network Model](images/network.png){width=5in}

**সুবিধা:** M:N সম্পর্ক প্রকাশ করা যায়; Redundancy কম; Data খোঁজার অনেক পথ।

**অসুবিধা:** গঠন জটিল; Pointer-এর কারণে কাঠামো পরিবর্তন কঠিন; Programmer-কে পুরো কাঠামো জানতে হয়।

### Hierarchical বনাম Network Model

| বিষয় | Hierarchical Model | Network Model |
|---|---|---|
| কাঠামো | Tree | Graph |
| Parent সংখ্যা | একটি Child-এর **একটি** Parent | একটি Child-এর **একাধিক** Parent |
| সম্পর্ক | শুধু 1:1 ও 1:N | 1:1, 1:N ও **M:N** |
| Redundancy | বেশি | কম |
| জটিলতা | সহজ | জটিল |
| Data খোঁজা | শুধু Root থেকে | একাধিক পথে |
| উদাহরণ | IBM IMS | IDMS (CODASYL) |

## মনে রাখার টিপস

- **Rectangle = Entity, Diamond = Relationship, Ellipse = Attribute।** "Double" মানেই বিশেষ: Double Rectangle = Weak, Double Ellipse = Multivalued, Double Line = Total Participation।
- M:N সম্পর্ক → সবসময় একটি আলাদা Table।
- Specialization = ভাঙা (ওপর থেকে নিচে), Generalization = জোড়া (নিচ থেকে ওপরে)।

## অধ্যায় ৩: প্রশ্নোত্তর

**অতিসংক্ষিপ্ত প্রশ্ন ও উত্তর**

1. **Data Model কী?** Data, সম্পর্ক, অর্থ ও Constraint বর্ণনার ধারণাগত সরঞ্জাম।
2. **Entity কী?** বাস্তব জগতের আলাদাভাবে চেনা যায় এমন বস্তু, যেমন একজন ছাত্র।
3. **E-R Diagram কী?** E-R Model-এর চিত্ররূপ।
4. **Primary Key কী?** যে Candidate Key দিয়ে প্রতিটি Row অনন্যভাবে চেনা যায়; NULL ও Duplicate হতে পারে না।
5. **Super Key কী?** যে Attribute সেট Row-কে অনন্যভাবে চেনায় (অতিরিক্ত Attribute থাকতে পারে)।
6. **Foreign Key কী?** অন্য Table-এর Primary Key-কে নির্দেশকারী Attribute।
7. **Relational Data Model কী?** Data ও সম্পর্ক Table আকারে প্রকাশের Model।
8. **Network Data Model কী?** Graph আকারের Model, যেখানে Child-এর একাধিক Parent থাকে।
9. **Mapping Cardinality কত প্রকার?** চার প্রকার: 1:1, 1:N, N:1, M:N।
10. **Weak Entity-র Symbol কী?** Double Rectangle।
11. **Multivalued Attribute-এর উদাহরণ দাও।** একজন ছাত্রের একাধিক ফোন নম্বর।
12. **Aggregation কেন দরকার?** Relationship-এর সঙ্গে Relationship যুক্ত করার জন্য।

**সংক্ষিপ্ত ও রচনামূলক প্রশ্ন**

1. Strong ও Weak Entity-র পার্থক্য লেখ।
2. E-R Diagram-এর ৬টি Symbol অঙ্কন কর।
3. E-R Diagram-এ ব্যবহৃত বিভিন্ন Attribute বর্ণনা কর।
4. Database-এ ব্যবহৃত বিভিন্ন Key-এর বর্ণনা দাও।
5. Mapping Cardinality সংক্ষেপে লেখ এবং বিভিন্ন Mapping Constraint-এর জন্য E-R Diagram বর্ণনা কর।
6. চিত্রসহ Hierarchical Data Model বর্ণনা কর।
7. Network ও Hierarchical Data Model-এর পার্থক্য লেখ।
8. Specialization, Generalization ও Aggregation চিত্রসহ বর্ণনা কর।
9. একটি পলিটেকনিকের (বা লাইব্রেরির) জন্য E-R Diagram আঁক এবং তা থেকে Table তৈরি কর।


# অধ্যায় ৪: রিলেশনাল ডাটাবেস ও কুয়েরি ল্যাংগুয়েজ

> **এক নজরে:** Relational Model-এর পরিভাষা (Relation, Tuple, Attribute, Domain, Degree, Cardinality); Query Language কী; Formal ও Commercial Query Language; Relational Algebra-র মৌলিক ও অতিরিক্ত Operation (উদাহরণসহ); Unary ও Binary Operator; Relational Calculus; SQL, QBE ও Datalog।

**আগের অধ্যায়ের সঙ্গে সম্পর্ক:** অধ্যায় ৩-এ E-R Diagram থেকে Table বানানো শিখেছেন। এই Table-গুলোই Relational Model। এবার দেখব Table থেকে কীভাবে প্রশ্নের (Query) উত্তর বের করতে হয়।

## Relational Model-এর পরিভাষা

| পরিভাষা | অর্থ | `student` Table-এ উদাহরণ |
|---|---|---|
| **Relation** | Table | student |
| **Tuple** | Row (একটি Record) | (101, Rahim, 1, 6, 3.75, Dhaka, ...) |
| **Attribute** | Column | roll, name, cgpa |
| **Domain** | একটি Attribute-এর সম্ভাব্য সব মানের সেট | semester-এর Domain = {1, 2, ..., 8} |
| **Degree (Arity)** | Attribute (Column)-এর সংখ্যা | 7 |
| **Cardinality** | Tuple (Row)-এর সংখ্যা | 10 |
| **Relation Schema** | Relation-এর নাম ও Attribute-এর তালিকা | student(roll, name, dept_id, semester, cgpa, city, phone) |
| **Relation Instance** | নির্দিষ্ট মুহূর্তের Tuple-গুলো | এখনকার ১০টি Row |

**Relation-এর বৈশিষ্ট্য:** প্রতিটি Tuple অনন্য (Duplicate Row নেই); Row ও Column-এর ক্রম অর্থহীন; প্রতিটি ঘরে একটিমাত্র (Atomic) মান থাকে।

## Query Language

**Query Language:** **যে ভাষার মাধ্যমে ব্যবহারকারী Database থেকে তথ্য চাইতে (Query) পারেন।**

**Query Language-এর কাজ:** Data খোঁজা (Retrieve), Filter করা, সাজানো, হিসাব করা (যোগফল, গড়), একাধিক Table যুক্ত করা, আর Data যোগ/পরিবর্তন/মোছা।

| Formal (Pure) Query Language | Commercial Query Language |
|---|---|
| গাণিতিক ভিত্তিসম্পন্ন তাত্ত্বিক ভাষা | বাস্তবে DBMS-এ ব্যবহৃত ভাষা |
| Commercial ভাষার ভিত্তি | Formal ভাষার ওপর তৈরি, আরও সুবিধাসহ |
| শুধু Data খোঁজা (Retrieval) | খোঁজা, যোগ, পরিবর্তন, মোছা, কাঠামো তৈরি সবই |
| Relational Algebra, Tuple ও Domain Relational Calculus | SQL, QBE, Datalog |

## Relational Algebra

**Relational Algebra:** **একটি Procedural Query Language**, যেখানে এক বা একাধিক Relation-এর ওপর কিছু Operation চালিয়ে **ফলাফল হিসেবে নতুন একটি Relation** পাওয়া যায়।

**Operator দুই ধরনের:**

- **Unary Operator:** একটি Relation-এর ওপর কাজ করে: Select (σ), Project (π), Rename (ρ)।
- **Binary Operator:** দুটি Relation-এর ওপর কাজ করে: Union (∪), Set Difference (−), Cartesian Product (×), Intersection (∩), Join (⋈), Division (÷)।

### মৌলিক (Fundamental) Operation: ৬টি

| Operation | Symbol | কাজ |
|---|---|---|
| Select | σ (sigma) | শর্ত অনুযায়ী **Row** বাছাই |
| Project | π (pi) | নির্দিষ্ট **Column** বাছাই |
| Union | ∪ | দুই Relation-এর সব Tuple (Duplicate ছাড়া) |
| Set Difference | − | প্রথমটিতে আছে, দ্বিতীয়টিতে নেই |
| Cartesian Product | × | দুই Relation-এর প্রতিটি Tuple-এর সব সম্ভাব্য জোড়া |
| Rename | ρ (rho) | Relation বা Attribute-এর নাম বদলানো |

### ১. Select (σ): Row বাছাই

**σ** লিখে তার নিচে ছোট করে শর্ত, তারপর বন্ধনীতে Relation লেখা হয়। যেমন: CGPA 3.5-এর বেশি এমন ছাত্র:

> $\sigma_{cgpa > 3.5}(student)$

SQL-এ এর সমতুল্য রূপ ও ফলাফল:

```sql
SELECT * FROM student WHERE cgpa > 3.5;
```

**Output:**

| roll | name | dept_id | semester | cgpa | city | phone |
|---|---|---|---|---|---|---|
| 101 | Rahim | 1 | 6 | 3.75 | Dhaka | 01711111111 |
| 103 | Nila | 1 | 4 | 3.90 | Dhaka | NULL |
| 107 | Rina | 3 | 2 | 3.60 | Rajshahi | 01777777777 |
| 109 | Tania | 1 | 2 | 3.55 | Natore | 01799999999 |

_(মোট 4টি row)_

### ২. Project (π): Column বাছাই

**π** লিখে তার নিচে ছোট করে Attribute-এর তালিকা, তারপর বন্ধনীতে Relation লেখা হয়। Duplicate Row স্বয়ংক্রিয়ভাবে বাদ যায়। যেমন: ছাত্ররা কোন কোন শহরের?

> $\pi_{city}(student)$

```sql
SELECT DISTINCT city FROM student;
```

**Output:**

| city |
|---|
| Dhaka |
| Sirajganj |
| Bogura |
| Pabna |
| Rajshahi |
| Natore |

_(মোট 6টি row)_

**Select ও Project একসঙ্গে:** কম্পিউটার বিভাগের ছাত্রদের নাম ও CGPA:

> $\pi_{name,\ cgpa}(\sigma_{dept\_id = 1}(student))$

```sql
SELECT name, cgpa FROM student WHERE dept_id = 1;
```

**Output:**

| name | cgpa |
|---|---|
| Rahim | 3.75 |
| Karim | 3.20 |
| Nila | 3.90 |
| Tania | 3.55 |

_(মোট 4টি row)_

### ৩. Union (∪)

দুটি Relation-এর সব Tuple, Duplicate ছাড়া। **শর্ত (Union Compatibility):** দুই Relation-এর Attribute সংখ্যা সমান হতে হবে, আর সংশ্লিষ্ট Attribute-এর Domain একই হতে হবে।

যেমন: যেসব কোর্সে **Rahim (101)** অথবা **Nila (103)** ভর্তি:

> $\pi_{course\_code}(\sigma_{roll=101}(enrollment)) \cup \pi_{course\_code}(\sigma_{roll=103}(enrollment))$

```sql
SELECT course_code FROM enrollment WHERE roll = 101
UNION
SELECT course_code FROM enrollment WHERE roll = 103;
```

**Output:**

| course_code |
|---|
| 28541 |
| 28561 |
| 28562 |

_(মোট 3টি row)_

### ৪. Set Difference (−)

প্রথম Relation-এ আছে কিন্তু দ্বিতীয়টিতে নেই। যেমন: Rahim যে কোর্সে আছে কিন্তু Nila নেই:

> $\pi_{course\_code}(\sigma_{roll=101}(enrollment)) - \pi_{course\_code}(\sigma_{roll=103}(enrollment))$

```sql
SELECT course_code FROM enrollment WHERE roll = 101
EXCEPT
SELECT course_code FROM enrollment WHERE roll = 103;
```

**Output:**

| course_code |
|---|
| 28562 |

_(মোট 1টি row)_

(MySQL 8.0.31 থেকে `EXCEPT` আর `INTERSECT` সমর্থিত।)

### ৫. Cartesian Product (×)

প্রথম Relation-এর প্রতিটি Tuple-এর সঙ্গে দ্বিতীয়টির প্রতিটি Tuple জোড়া লাগে। Row সংখ্যা = r₁ × r₂। নিজে একা খুব কাজের নয়, কিন্তু Join-এর ভিত্তি।

```sql
SELECT COUNT(*) AS student_rows,
       (SELECT COUNT(*) FROM department) AS dept_rows,
       (SELECT COUNT(*) FROM student CROSS JOIN department) AS product_rows
FROM student;
```

**Output:**

| student_rows | dept_rows | product_rows |
|---|---|---|
| 10 | 4 | 40 |

_(মোট 1টি row)_

১০ × ৪ = ৪০টি জোড়া, যার বেশিরভাগই অর্থহীন (Rahim-কে Civil বিভাগের সঙ্গেও জোড়া দেওয়া হয়েছে)। তাই Product-এর পরে Select দিয়ে মিল থাকা জোড়া রাখা হয়। এটাই Join।

### ৬. Rename (ρ)

> $\rho_{s}(student)$: student Relation-কে s নামে ব্যবহার। একই Table নিজের সঙ্গে তুলনা (Self Join) করতে লাগে।

### অতিরিক্ত (Additional) Operation

**Set Intersection (∩):** দুটিতেই আছে। r ∩ s = r − (r − s)। যেমন: Rahim আর Nila দুজনেই যে কোর্সে:

```sql
SELECT course_code FROM enrollment WHERE roll = 101
INTERSECT
SELECT course_code FROM enrollment WHERE roll = 103;
```

**Output:**

| course_code |
|---|
| 28541 |
| 28561 |

_(মোট 2টি row)_

**Natural Join (⋈):** দুই Relation-এর **একই নামের Attribute-এর মান মিলিয়ে** Tuple জোড়া দেয়। সমান Attribute একবারই রাখে। = Cartesian Product + Select + Project।

> $\pi_{name,\ dept\_name}(student \bowtie department)$

```sql
SELECT name, dept_name
FROM student NATURAL JOIN department
ORDER BY name;
```

**Output:**

| name | dept_name |
|---|---|
| Hasan | Mechanical |
| Jamal | Electrical |
| Karim | Computer |
| Mitu | Civil |
| Nila | Computer |
| Rahim | Computer |
| Rina | Electrical |
| Sumon | Civil |
| Tania | Computer |

_(মোট 9টি row)_

Arif নেই, কারণ তাঁর `dept_id` NULL, তাই কোনো বিভাগের সঙ্গে মেলেনি।

**Theta Join ($\bowtie_{\theta}$):** যেকোনো শর্তে (=, <, > ইত্যাদি) Join। শর্ত শুধু "=" হলে তাকে **Equi Join** বলে।

**Outer Join:** মিল না পাওয়া Tuple-ও রাখে, অনুপস্থিত মান NULL দিয়ে পূরণ করে। Left (⟕), Right (⟖) ও Full (⟗)। SQL উদাহরণ অধ্যায় ৫-এ।

**Division (÷):** "**সবগুলোর** সঙ্গে সম্পর্কিত" প্রশ্নের জন্য। যেমন: কম্পিউটার বিভাগের **সব** কোর্সে ভর্তি হয়েছে কোন ছাত্র?

> $\pi_{roll,\ course\_code}(enrollment) \div \pi_{course\_code}(\sigma_{dept\_id=1}(course))$

SQL-এ "এমন কোনো কোর্স নেই যেটায় সে ভর্তি নয়" (দুবার NOT EXISTS):

```sql
SELECT s.roll, s.name
FROM student s
WHERE NOT EXISTS (
    SELECT * FROM course c
    WHERE c.dept_id = 1
      AND NOT EXISTS (
          SELECT * FROM enrollment e
          WHERE e.roll = s.roll AND e.course_code = c.course_code));
```

**Output:**

| roll | name |
|---|---|
| 101 | Rahim |

_(মোট 1টি row)_

**Assignment (←):** মধ্যবর্তী ফল একটি অস্থায়ী নামে রাখা। যেমন: $temp \leftarrow \sigma_{dept\_id=1}(student)$।

**Extended Operation:** Generalized Projection (π-তে হিসাব, যেমন salary × 12), **Aggregate Function (𝒢)**: sum, avg, count, min, max (যেমন: $_{dept\_id}\mathcal{G}_{avg(cgpa)}(student)$)।

## Relational Calculus (সংক্ষেপে)

Relational Algebra বলে **কীভাবে** উত্তর বের করতে হবে (Procedural)। আর Relational Calculus শুধু বলে **কী** চাই (**Non-procedural**)।

- **Tuple Relational Calculus (TRC):** Variable হলো Tuple।
  { t | t ∈ student ∧ t[cgpa] > 3.5 }, অর্থাৎ সব t, যেখানে t student-এর সদস্য এবং t-এর cgpa 3.5-এর বেশি।
- **Domain Relational Calculus (DRC):** Variable হলো Attribute-এর মান (Domain)।
  { < n > | ∃ r, d, s, c (< r, n, d, s, c, ... > ∈ student ∧ c > 3.5) }

## SQL, QBE ও Datalog

**SQL (Structured Query Language):** সবচেয়ে প্রচলিত Commercial Query Language। Relational Algebra ও Calculus-এর মিশ্রণ। অধ্যায় ৫-এ বিস্তারিত।

**QBE (Query By Example):** **IBM-এর তৈরি (1970-এর দশক) একটি Graphical Query Language।** ব্যবহারকারী Table-এর একটি **কঙ্কাল (Skeleton)** পূরণ করে উদাহরণ দিয়ে প্রশ্ন করেন। Microsoft Access-এর Query Design View এর আধুনিক রূপ।

| student | roll | name | dept_id | cgpa |
|---|---|---|---|---|
| | | P. | | > 3.5 |

এখানে `P.` মানে "Print (দেখাও)"। অর্থাৎ যাদের cgpa > 3.5, তাদের নাম দেখাও।

**Datalog:** **Prolog-এর ওপর ভিত্তি করে তৈরি, নিয়ম (Rule)-ভিত্তিক একটি Non-procedural Query Language।**

```text
good_student(N) :- student(R, N, D, S, C, Ci, P), C > 3.5.
? good_student(N).
```

অর্থাৎ N একজন good_student, যদি student Relation-এ N নামের এমন কেউ থাকে যার CGPA (C) 3.5-এর বেশি।

### SQL, QBE ও Datalog-এর পার্থক্য

| বিষয় | SQL | QBE | Datalog |
|---|---|---|---|
| ধরন | Text-ভিত্তিক, Declarative | Graphical (Skeleton Table পূরণ) | Rule-ভিত্তিক (Logic) |
| ভিত্তি | Relational Algebra ও Calculus | Domain Relational Calculus | Logic Programming (Prolog) |
| ব্যবহার | সব RDBMS-এ (MySQL, Oracle) | MS Access, Query Builder | গবেষণা, Recursive Query |
| শেখা | মাঝারি | খুব সহজ | তুলনামূলক কঠিন |
| Recursive Query | সীমিত (WITH RECURSIVE) | না | খুব ভালোভাবে |

## SQL পরিচিতি

**SQL (Structured Query Language):** **Relational Database তৈরি, পরিচালনা ও তা থেকে তথ্য খোঁজার জন্য ব্যবহৃত Standard ভাষা।** 1970-এর দশকে IBM-এ "SEQUEL" নামে তৈরি হয়। পরে ANSI (1986) ও ISO (1987) একে Standard করে।

**SQL-এর বৈশিষ্ট্য:**

1. ইংরেজির মতো সহজ, Non-procedural (শুধু "কী চাই" বলতে হয়)।
2. সব প্রধান RDBMS-এ (MySQL, Oracle, SQL Server) চলে।
3. একটি Command দিয়ে অনেক Row-এর কাজ করা যায়।
4. Case-insensitive (SELECT আর select একই)।
5. Database তৈরি থেকে নিরাপত্তা পর্যন্ত সব কাজ করা যায়।

**SQL-এর অংশসমূহ (Parts of SQL):**

1. **DDL:** কাঠামো তৈরি ও পরিবর্তন (CREATE, ALTER, DROP)।
2. **DML:** Data নিয়ে কাজ (SELECT, INSERT, UPDATE, DELETE)।
3. **View Definition:** View তৈরি।
4. **Transaction Control:** COMMIT, ROLLBACK।
5. **Integrity:** Constraint নির্ধারণ।
6. **Authorization:** GRANT, REVOKE।
7. **Embedded SQL ও Dynamic SQL:** Java, C, PHP-র মতো ভাষার ভেতরে SQL লেখা।

## SQL Query-র মূল কাঠামো (Basic Clauses)

SQL Query-র মূল তিনটি Clause:

```text
SELECT  A1, A2, ..., An      -- কোন Column চাই        (Relational Algebra-র π)
FROM    r1, r2, ..., rm      -- কোন Table থেকে        (Cartesian Product ×)
WHERE   P;                   -- কোন শর্তে (ঐচ্ছিক)    (Select σ)
```

এর সমতুল্য Relational Algebra: $\pi_{A1, ..., An}(\sigma_{P}(r1 \times r2 \times ... \times rm))$

**পূর্ণ Syntax (লেখার ক্রম):**

```text
SELECT   [DISTINCT] column_list
FROM     table_list
[WHERE   condition]
[GROUP BY column_list]
[HAVING  group_condition]
[ORDER BY column [ASC|DESC]]
[LIMIT   n];
```

**চালানোর ক্রম (Execution Order):** FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT।

| `BETWEEN a AND b` | a থেকে b-এর মধ্যে (দুই প্রান্তসহ) |

## Aggregate Function

**Aggregate Function:** **অনেকগুলো Row-এর মান নিয়ে একটি মাত্র ফল দেয় এমন Function।**

| Function | কাজ |
|---|---|
| `COUNT()` | সংখ্যা গোনা (`COUNT(*)` সব Row; `COUNT(col)` NULL বাদে) |
| `SUM()` | যোগফল |
| `AVG()` | গড় |
| `MAX()` | সর্বোচ্চ |
| `MIN()` | সর্বনিম্ন |

```sql
SELECT COUNT(*)            AS total_students,
       COUNT(phone)        AS has_phone,
       ROUND(AVG(cgpa), 2) AS avg_cgpa,
       MAX(cgpa)           AS highest,
       MIN(cgpa)           AS lowest
FROM student;
```

**Output:**

| total_students | has_phone | avg_cgpa | highest | lowest |
|---|---|---|---|---|
| 10 | 8 | 3.37 | 3.90 | 2.80 |

_(মোট 1টি row)_

`COUNT(*)` = 10, কিন্তু `COUNT(phone)` = 8, কারণ দুজনের phone NULL। AVG, MAX আর MIN-ও NULL বাদ দিয়ে হিসাব করে (Arif-এর cgpa NULL)।

### GROUP BY ও HAVING

**GROUP BY:** একই মানের Row-গুলোকে একটি গ্রুপে এনে প্রতিটি গ্রুপের জন্য Aggregate হিসাব করে।
**HAVING:** গ্রুপের ওপর শর্ত (WHERE হলো Row-এর ওপর শর্ত)।

```sql
SELECT dept_id,
       COUNT(*)            AS students,
       ROUND(AVG(cgpa), 2) AS avg_cgpa
FROM student
WHERE dept_id IS NOT NULL
GROUP BY dept_id
HAVING COUNT(*) >= 2
ORDER BY avg_cgpa DESC;
```

**Output:**

| dept_id | students | avg_cgpa |
|---|---|---|
| 1 | 4 | 3.60 |
| 3 | 2 | 3.35 |
| 2 | 2 | 3.20 |

_(মোট 3টি row)_

| WHERE | HAVING |
|---|---|
| Row filter করে | Group filter করে |
| GROUP BY-এর **আগে** চলে | GROUP BY-এর **পরে** চলে |
| Aggregate Function ব্যবহার করা যায় না | Aggregate Function ব্যবহার করা যায় |

## JOIN

**JOIN:** **একাধিক Table-এর সম্পর্কিত Row একটি সাধারণ Column-এর ভিত্তিতে একসঙ্গে দেখানো।**

| JOIN | ফলাফল |
|---|---|
| **INNER JOIN** | দুই Table-এই মিল আছে এমন Row |
| **LEFT (OUTER) JOIN** | বাঁ Table-এর সব Row + ডান Table-এর মিল থাকা Row (মিল না থাকলে NULL) |
| **RIGHT (OUTER) JOIN** | ডান Table-এর সব Row + বাঁ Table-এর মিল থাকা Row |
| **FULL OUTER JOIN** | দুই Table-এর সব Row (MySQL-এ নেই; LEFT ∪ RIGHT দিয়ে করা হয়) |
| **CROSS JOIN** | Cartesian Product |
| **SELF JOIN** | Table-কে নিজের সঙ্গে Join |
| **NATURAL JOIN** | একই নামের Column দিয়ে স্বয়ংক্রিয় Join |

**INNER JOIN:** প্রতিটি ছাত্রের বিভাগের নাম:

```sql
SELECT s.roll, s.name, d.dept_name
FROM student s
INNER JOIN department d ON s.dept_id = d.dept_id
WHERE s.semester = 6;
```

**Output:**

| roll | name | dept_name |
|---|---|---|
| 101 | Rahim | Computer |
| 102 | Karim | Computer |
| 104 | Sumon | Civil |
| 106 | Jamal | Electrical |
| 108 | Hasan | Mechanical |

_(মোট 5টি row)_

**LEFT JOIN:** সব বিভাগ ও তাদের শিক্ষক সংখ্যা (শিক্ষক না থাকলেও বিভাগ দেখাবে):

```sql
SELECT d.dept_name, COUNT(t.teacher_id) AS teachers
FROM department d
LEFT JOIN teacher t ON t.dept_id = d.dept_id
GROUP BY d.dept_id, d.dept_name;
```

**Output:**

| dept_name | teachers |
|---|---|
| Civil | 1 |
| Computer | 2 |
| Electrical | 1 |
| Mechanical | 1 |

_(মোট 4টি row)_

**তিন Table-এর JOIN:** কে কোন কোর্সে কত নম্বর পেয়েছে (কম্পিউটার বিভাগের কোর্স):

```sql
SELECT s.name, c.title, e.marks
FROM enrollment e
```

## Subquery (Nested Query)

```sql
CREATE VIEW student_result AS
```

```text
CREATE INDEX idx_student_city ON student(city);
```

## PL/SQL পরিচিতি

**PL/SQL (Procedural Language extension to SQL):** **Oracle-এর তৈরি একটি ভাষা, যা SQL-এর সঙ্গে Programming ভাষার সুবিধা (Variable, Condition, Loop, Function, Exception Handling) যুক্ত করে।**

SQL একবারে একটি Statement চালায়। PL/SQL একাধিক SQL Statement আর যুক্তিকে (Logic) একটি **Block**-এ বেঁধে একসঙ্গে Server-এ পাঠায়।

**PL/SQL-এর সুবিধা:**

1. Procedural ক্ষমতা: IF, LOOP, Variable।
2. Network traffic কম: পুরো Block একবারে যায়।
3. Error Handling (EXCEPTION)।
4. Procedure/Function বানিয়ে বারবার ব্যবহার (Reusability)।
5. নিরাপত্তা: ব্যবহারকারীকে Table-এর বদলে শুধু Procedure চালানোর অনুমতি দেওয়া যায়।
6. Trigger দিয়ে স্বয়ংক্রিয় কাজ।

**SQL বনাম PL/SQL:**

| SQL | PL/SQL |
|---|---|
| Non-procedural (কী চাই) | Procedural (কীভাবে করব) |
| একবারে একটি Statement | একাধিক Statement-এর Block |
| Variable, Loop, IF নেই | আছে |
| Data নিয়ে কাজ | Application Logic তৈরি |
| সব RDBMS-এ | মূলত Oracle (MySQL-এ Stored Program, SQL Server-এ T-SQL) |

### PL/SQL Block-এর গঠন

```text
DECLARE            -- (ঐচ্ছিক) Variable, Constant, Cursor ঘোষণা
    v_name   student.name%TYPE;     -- Column-এর মতো একই Type
    v_cgpa   NUMBER(3,2);
BEGIN              -- (বাধ্যতামূলক) মূল কাজ: SQL + Logic
    SELECT name, cgpa INTO v_name, v_cgpa
    FROM student WHERE roll = 101;

    IF v_cgpa >= 3.5 THEN
        DBMS_OUTPUT.PUT_LINE(v_name || ' : Excellent');
    ELSE
        DBMS_OUTPUT.PUT_LINE(v_name || ' : Good');
    END IF;
EXCEPTION          -- (ঐচ্ছিক) Error সামলানো
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('No student found');
END;               -- (বাধ্যতামূলক)
/
```

- `%TYPE`: Variable-এর Type Column-এর Type অনুযায়ী ঠিক হয়।
- `SELECT ... INTO`: Query-র ফল Variable-এ রাখা।
- `DBMS_OUTPUT.PUT_LINE`: Screen-এ লেখা দেখানো (Oracle)।
- `||`: String জোড়া লাগানো।

### Control Structure (Oracle PL/SQL)

```text
-- IF-ELSIF-ELSE
IF marks >= 80 THEN grade := 'A+';
ELSIF marks >= 70 THEN grade := 'A';
ELSE grade := 'B';
END IF;

-- Basic LOOP
LOOP
    i := i + 1;
    EXIT WHEN i > 5;
END LOOP;

-- WHILE LOOP
WHILE i <= 5 LOOP
    i := i + 1;
END LOOP;

-- FOR LOOP
FOR i IN 1..5 LOOP
    DBMS_OUTPUT.PUT_LINE(i);
END LOOP;
```

### Cursor

**Cursor:** **SQL Query-র ফলাফলের (একাধিক Row) ওপর একটি Pointer, যা দিয়ে Row-গুলো একটি একটি করে প্রক্রিয়া করা যায়।**

- **Implicit Cursor:** প্রতিটি SQL Statement-এর জন্য Oracle নিজে তৈরি করে (যেমন `SQL%ROWCOUNT`)।
- **Explicit Cursor:** Programmer একাধিক Row-এর Query-র জন্য নিজে ঘোষণা করেন। ধাপ: **DECLARE → OPEN → FETCH → CLOSE**।

```text
DECLARE
    CURSOR c_stu IS SELECT name, cgpa FROM student WHERE dept_id = 1;
    v_name student.name%TYPE;
    v_cgpa student.cgpa%TYPE;
BEGIN
    OPEN c_stu;
    LOOP
        FETCH c_stu INTO v_name, v_cgpa;
        EXIT WHEN c_stu%NOTFOUND;
        DBMS_OUTPUT.PUT_LINE(v_name || ' - ' || v_cgpa);
    END LOOP;
    CLOSE c_stu;
END;
/
```

**Cursor Attribute:** `%FOUND`, `%NOTFOUND`, `%ROWCOUNT`, `%ISOPEN`।

### Procedure ও Function (Oracle)

| Procedure | Function |
|---|---|
| একটি কাজ সম্পন্ন করে | একটি মান হিসাব করে **ফেরত দেয় (RETURN)** |
| মান ফেরত দেওয়া বাধ্যতামূলক নয় (OUT parameter দিয়ে দেওয়া যায়) | অবশ্যই একটি মান RETURN করে |
| `EXEC proc_name;` বা `CALL` দিয়ে চালানো | SELECT-এর ভেতরে ব্যবহার করা যায় |

```text
CREATE OR REPLACE PROCEDURE raise_salary (p_dept IN NUMBER, p_pct IN NUMBER) AS
BEGIN
    UPDATE teacher SET salary = salary + salary * p_pct / 100 WHERE dept_id = p_dept;
    COMMIT;
END;
/

CREATE OR REPLACE FUNCTION get_grade (p_marks IN NUMBER) RETURN VARCHAR2 AS
BEGIN
    IF p_marks >= 80 THEN RETURN 'A+';
    ELSIF p_marks >= 70 THEN RETURN 'A';
    ELSE RETURN 'B';
    END IF;
END;
/
```

### Exception Handling

**Exception:** Program চলার সময় ঘটা Error। PL/SQL-এ EXCEPTION অংশে সামলানো হয়।

- **Predefined Exception:** `NO_DATA_FOUND` (কোনো Row পাওয়া যায়নি), `TOO_MANY_ROWS` (একটির বেশি Row), `ZERO_DIVIDE` (শূন্য দিয়ে ভাগ), `DUP_VAL_ON_INDEX` (Duplicate Key)।
- **User-defined Exception:** Programmer নিজে ঘোষণা করে `RAISE` দিয়ে চালু করেন।

### Cursor (MySQL)

প্রতিটি বিভাগের ছাত্রদের নাম একটি লাইনে জোড়া দেওয়ার Procedure। Cursor দিয়ে Row ধরে ধরে পড়া হচ্ছে:

```sql
DELIMITER //
CREATE PROCEDURE list_names(IN p_dept INT)
BEGIN
    DECLARE done INT DEFAULT 0;
    DECLARE v_name VARCHAR(40);
    DECLARE result VARCHAR(500) DEFAULT '';
    DECLARE c_stu CURSOR FOR
        SELECT name FROM student WHERE dept_id = p_dept ORDER BY roll;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;

    OPEN c_stu;
    read_loop: LOOP
        FETCH c_stu INTO v_name;
        IF done = 1 THEN LEAVE read_loop; END IF;
        SET result = CONCAT(result, IF(result = '', '', ', '), v_name);
    END LOOP;
    CLOSE c_stu;

    SELECT p_dept AS dept_id, result AS students;
END //
DELIMITER ;
```

```sql
CALL list_names(1);
```

**Output:**

| dept_id | students |
|---|---|
| 1 | Rahim, Karim, Nila, Tania |

_(মোট 1টি row)_

- `DECLARE ... CURSOR FOR`: Cursor ঘোষণা।
- `DECLARE CONTINUE HANDLER FOR NOT FOUND`: Row শেষ হলে `done = 1` (Oracle-এর `%NOTFOUND`-এর কাজ)।
- `OPEN → FETCH (Loop) → CLOSE`: Oracle-এর মতোই ধাপ।

**Trigger** অধ্যায় ৬-এ (Integrity) আর **Transaction** (COMMIT, ROLLBACK) অধ্যায় ৯-এ দেখবেন।

## মনে রাখার টিপস

- SQL লেখার ক্রম: **S-F-W-G-H-O** (SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY)। চলার ক্রম: **F-W-G-H-S-O**।
- `NULL`-এর তুলনা সবসময় `IS NULL` দিয়ে, `= NULL` দিয়ে নয়।
- WHERE = Row, HAVING = Group।
- PL/SQL Block: **DECLARE – BEGIN – EXCEPTION – END** (BEGIN আর END বাধ্যতামূলক)।
- Cursor-এর ধাপ: **D-O-F-C** (Declare, Open, Fetch, Close)।

## অধ্যায় ৫: প্রশ্নোত্তর

**অতিসংক্ষিপ্ত প্রশ্ন ও উত্তর**

1. **SQL কী?** Relational Database তৈরি, পরিচালনা ও তথ্য খোঁজার Standard ভাষা।
2. **SQL-এর মূল Clause কী কী?** SELECT, FROM, WHERE (সঙ্গে GROUP BY, HAVING, ORDER BY)।
3. **Aggregate Function-গুলোর নাম লেখ।** COUNT, SUM, AVG, MAX, MIN।
4. **SELECT Statement-এর কাজ কী?** Database থেকে Data খুঁজে আনা।
5. **View কী?** একটি সংরক্ষিত Query, যা Virtual Table হিসেবে কাজ করে।
6. **Index কী?** দ্রুত খোঁজার জন্য Data Structure।
7. **PL/SQL কী?** SQL-এর সঙ্গে Programming সুবিধা যুক্ত Oracle-এর ভাষা।
8. **Cursor কী?** Query-র ফলাফলের Row একটি একটি করে প্রক্রিয়া করার Pointer।
9. **Procedure ও Function-এর মূল পার্থক্য কী?** Function অবশ্যই একটি মান RETURN করে।
10. **WHERE ও HAVING-এর পার্থক্য কী?** WHERE Row filter করে, HAVING Group filter করে।
11. **LIKE-এ % ও _ কী বোঝায়?** % = যেকোনো সংখ্যক অক্ষর, _ = একটি অক্ষর।
12. **Query Language-এর কাজ কী?** Data খোঁজা, Filter, সাজানো, হিসাব, যোগ-পরিবর্তন-মোছা।

# অধ্যায় ৬: ইন্টিগ্রিটি ও সিকিউরিটি

> **এক নজরে:** Database Integrity কী; Integrity Constraint-এর প্রকারভেদ (Domain, Entity, Referential, Key, NOT NULL, CHECK, Assertion); Trigger; Database Security-র প্রয়োজনীয়তা ও স্তর; Authentication ও Authorization; Privilege; GRANT ও REVOKE; Role; View দিয়ে নিরাপত্তা; Encryption ও এর কৌশল; SQL Injection।

**আগের অধ্যায়ের সঙ্গে সম্পর্ক:** অধ্যায় ১-এ File System-এর "Integrity Problem" আর "Security Problem" দেখেছিলেন। DBMS এই দুটি সমস্যা কীভাবে সমাধান করে, এই অধ্যায়ে তা দেখবেন।

## Database Integrity

**Database Integrity:** **Database-এ সংরক্ষিত Data-র নির্ভুলতা (Accuracy), সামঞ্জস্যতা (Consistency) ও বিশ্বাসযোগ্যতা (Reliability) বজায় রাখা।**

**Integrity Constraint:** **যে নিয়মগুলো নিশ্চিত করে যে ভুল বা অসংগত Data Database-এ ঢুকতে পারবে না।** Constraint ভাঙলে DBMS ওই কাজ বাতিল করে দেয়।

> **উদাহরণ:** CGPA কখনো 5.00 হতে পারে না, রোল নম্বর দুজনের এক হতে পারে না, আর অস্তিত্বহীন বিভাগে ছাত্র ভর্তি হতে পারে না।

### Integrity Constraint-এর প্রকারভেদ

| Constraint | কাজ | SQL |
|---|---|---|
| **Domain Constraint** | Attribute-এর মান তার Domain (Type ও সীমা)-এর মধ্যে থাকবে | Data Type, `CHECK` |
| **NOT NULL** | মান খালি রাখা যাবে না | `NOT NULL` |
| **Entity Integrity** | Primary Key NULL বা Duplicate হতে পারবে না | `PRIMARY KEY` |
| **Key (Unique) Constraint** | মান অনন্য হবে | `UNIQUE` |
| **Referential Integrity** | Foreign Key-র মান অবশ্যই Parent Table-এ থাকতে হবে (অথবা NULL) | `FOREIGN KEY ... REFERENCES` |
| **CHECK Constraint** | নির্দিষ্ট শর্ত মানতে হবে | `CHECK (cgpa BETWEEN 0 AND 4)` |
| **Assertion** | পুরো Database-এর ওপর একটি শর্ত (একাধিক Table জুড়ে) | `CREATE ASSERTION` (SQL Standard; MySQL-এ নেই, Trigger দিয়ে করা হয়) |

**উদাহরণ: Constraint ভাঙলে কী হয়?**

**(ক) Entity Integrity:** একই রোল দুবার:

```sql
INSERT INTO student (roll, name, dept_id, semester) VALUES (101, 'New Student', 1, 1);
```

**MySQL Error:**

```text
ERROR 1062 (23000): Duplicate entry '101' for key 'student.PRIMARY'
```

**(খ) Referential Integrity:** অস্তিত্বহীন বিভাগ (dept_id = 9):

```sql
INSERT INTO student (roll, name, dept_id, semester) VALUES (120, 'Test', 9, 1);
```

**MySQL Error:**

```text
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails (`polytechnic_db`.`student`, CONSTRAINT `student_ibfk_1` FOREIGN KEY (`dept_id`) REFERENCES `department` (`dept_id`))
```

**(গ) CHECK Constraint:** semester 1–8-এর বাইরে:

```sql
INSERT INTO student (roll, name, dept_id, semester) VALUES (121, 'Test', 1, 10);
```

**MySQL Error:**

```text
ERROR 3819 (HY000): Check constraint 'student_chk_1' is violated.
```

**(ঘ) Referential Integrity, মোছার সময়:** যে বিভাগের সঙ্গে ছাত্র, শিক্ষক বা কোর্স যুক্ত, সেটি মোছা যাবে না (এখানে প্রথমে `course` Table-এর Foreign Key বাধা দিয়েছে):

```sql
DELETE FROM department WHERE dept_id = 1;
```

**MySQL Error:**

```text
ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (`polytechnic_db`.`course`, CONSTRAINT `course_ibfk_1` FOREIGN KEY (`dept_id`) REFERENCES `department` (`dept_id`))
```

**Referential Action:** Parent Row মুছলে বা বদলালে Child Row-এর কী হবে, তা ঠিক করা যায়:

| Action | অর্থ |
|---|---|
| `ON DELETE RESTRICT` / `NO ACTION` | Child থাকলে Parent মুছতে দেবে না (ডিফল্ট) |
| `ON DELETE CASCADE` | Parent মুছলে Child-ও মুছে যাবে |
| `ON DELETE SET NULL` | Parent মুছলে Child-এর Foreign Key NULL হবে |
| `ON UPDATE CASCADE` | Parent-এর Key বদলালে Child-এরটাও বদলাবে |

## Trigger

**Trigger:** **একটি বিশেষ Stored Program, যা কোনো Table-এ নির্দিষ্ট ঘটনা (INSERT, UPDATE বা DELETE) ঘটলে স্বয়ংক্রিয়ভাবে চালু হয়।** একে **Event-Condition-Action (ECA)** নিয়মও বলে।

**Trigger-এর অংশ:** **Event** (কোন ঘটনায়: INSERT/UPDATE/DELETE), **Timing** (BEFORE বা AFTER), **Action** (কী কাজ হবে)।

**ব্যবহার:** জটিল Integrity নিয়ম প্রয়োগ, Audit Log (কে কখন কী বদলাল), স্বয়ংক্রিয় হিসাব (যেমন Stock কমানো), ভুল Data আটকানো।

**উদাহরণ ১: BEFORE INSERT Trigger দিয়ে নিয়ম প্রয়োগ।** নম্বর 0–100-এর বাইরে হলে আটকাবে:

```sql
DELIMITER //
CREATE TRIGGER trg_check_marks
BEFORE INSERT ON enrollment
FOR EACH ROW
BEGIN
    IF NEW.marks < 0 OR NEW.marks > 100 THEN
        SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = 'Marks must be between 0 and 100';
    END IF;
END //
DELIMITER ;
```

```sql
INSERT INTO enrollment VALUES (109, '28561', 120);
```

**MySQL Error:**

```text
ERROR 1644 (45000): Marks must be between 0 and 100
```

**উদাহরণ ২: AFTER UPDATE Trigger দিয়ে Audit Log।** শিক্ষকের বেতন বদলালে পুরনো ও নতুন বেতন আলাদা Table-এ লিখে রাখবে:

```sql
CREATE TABLE salary_audit (
    audit_id    INT AUTO_INCREMENT PRIMARY KEY,
    teacher_id  INT,
    old_salary  INT,
    new_salary  INT,
    changed_at  DATE
);

DELIMITER //
CREATE TRIGGER trg_salary_audit
AFTER UPDATE ON teacher
FOR EACH ROW
BEGIN
    IF OLD.salary <> NEW.salary THEN
        INSERT INTO salary_audit (teacher_id, old_salary, new_salary, changed_at)
        VALUES (OLD.teacher_id, OLD.salary, NEW.salary, '2026-11-27');
    END IF;
END //
DELIMITER ;

UPDATE teacher SET salary = salary + 5000 WHERE teacher_id = 2;
```

```sql
SELECT * FROM salary_audit;
```

**Output:**

| audit_id | teacher_id | old_salary | new_salary | changed_at |
|---|---|---|---|---|
| 1 | 2 | 48000 | 53000 | 2026-11-27 |

_(মোট 1টি row)_

```sql
UPDATE teacher SET salary = 48000 WHERE teacher_id = 2;   -- আগের মানে ফেরত
DROP TRIGGER trg_salary_audit;
DROP TABLE salary_audit;
```

- `NEW.column`: INSERT/UPDATE-এর নতুন মান। `OLD.column`: UPDATE/DELETE-এর আগের মান।
- `SIGNAL SQLSTATE '45000'`: নিজের Error তৈরি করে কাজ বাতিল করা।
- (উদাহরণে তারিখ স্থির রাখা হয়েছে। বাস্তবে `CURDATE()` বা `NOW()` লিখুন।)

**Oracle PL/SQL-এ একই Trigger:**

```text
CREATE OR REPLACE TRIGGER trg_check_marks
BEFORE INSERT ON enrollment
FOR EACH ROW
BEGIN
    IF :NEW.marks < 0 OR :NEW.marks > 100 THEN
        RAISE_APPLICATION_ERROR(-20001, 'Marks must be between 0 and 100');
    END IF;
END;
/
```

## Database Security

**Database Security:** **অননুমোদিত ব্যক্তির হাত থেকে Database-কে রক্ষা করা**: অবৈধভাবে পড়া (চুরি), পরিবর্তন বা নষ্ট করা থেকে।

**প্রয়োজনীয়তা:**

1. **গোপনীয়তা (Confidentiality):** বেতন, ফলাফল, ব্যাংক হিসাবের মতো ব্যক্তিগত তথ্য রক্ষা।
2. **অখণ্ডতা (Integrity):** কেউ যেন অবৈধভাবে নম্বর বা টাকার পরিমাণ বদলাতে না পারে।
3. **প্রাপ্যতা (Availability):** বৈধ ব্যবহারকারী যেন সবসময় Data পান।
4. আইনগত বাধ্যবাধকতা (যেমন ডিজিটাল নিরাপত্তা সংক্রান্ত আইন) পূরণ।
5. প্রতিষ্ঠানের সুনাম ও আর্থিক ক্ষতি রোধ।

**Security-র স্তর (Levels of Security):**

| স্তর | কী সুরক্ষা |
|---|---|
| **Physical** | Server রুমে তালা, CCTV, অগ্নি-নিরাপত্তা |
| **Human** | কর্মীদের সততা, Password শেয়ার না করা, প্রশিক্ষণ |
| **Operating System** | OS-এর নিরাপত্তা, Update, Antivirus |
| **Network** | Firewall, SSL/TLS Encryption |
| **Database System** | User Account, Password, Privilege, View, Audit |

## Authentication ও Authorization

- **Authentication (প্রমাণীকরণ):** **"আপনি কে?"** যাচাই করা, যেমন Username + Password, OTP, Fingerprint।
- **Authorization (অনুমোদন):** **"আপনি কী করতে পারবেন?"** নির্ধারণ করা। কোন User কোন Data-তে কোন কাজ করতে পারবেন।

### Authorization-এর প্রকার (Privilege)

**Data-র ওপর Authorization (Data Manipulation):**

1. **Read (SELECT)** Authorization: Data পড়ার অনুমতি।
2. **Insert** Authorization: নতুন Data যোগের অনুমতি।
3. **Update** Authorization: পরিবর্তনের অনুমতি।
4. **Delete** Authorization: মোছার অনুমতি।

**Schema-র ওপর Authorization (Schema Modification):**

1. **Index** Authorization: Index তৈরি/মোছা।
2. **Resource** Authorization: নতুন Table তৈরি।
3. **Alteration** Authorization: Table-এর কাঠামো পরিবর্তন (ALTER)।
4. **Drop** Authorization: Table মোছা।

### GRANT ও REVOKE (DCL)

```text
GRANT privilege_list ON database.table TO user [WITH GRANT OPTION];
REVOKE privilege_list ON database.table FROM user;
```

- `WITH GRANT OPTION`: প্রাপ্ত অনুমতি অন্যকে দেওয়ার ক্ষমতা।

**উদাহরণ:** অফিস সহকারীর জন্য একটি User, যিনি শুধু ছাত্রদের তালিকা দেখবেন আর ফোন নম্বর বদলাবেন:

```sql
DROP USER IF EXISTS 'office_user'@'localhost';
CREATE USER 'office_user'@'localhost' IDENTIFIED BY 'Office@2026';
GRANT SELECT, UPDATE (phone) ON polytechnic_db.student TO 'office_user'@'localhost';
```

```sql
SHOW GRANTS FOR 'office_user'@'localhost';
```

**Output:**

| Grants for office_user@localhost |
|---|
| GRANT USAGE ON *.* TO `office_user`@`localhost` |
| GRANT SELECT, UPDATE (`phone`) ON `polytechnic_db`.`student` TO `office_user`@`localhost` |

_(মোট 2টি row)_

```sql
REVOKE UPDATE (phone) ON polytechnic_db.student FROM 'office_user'@'localhost';
```

```sql
SHOW GRANTS FOR 'office_user'@'localhost';
```

**Output:**

| Grants for office_user@localhost |
|---|
| GRANT USAGE ON *.* TO `office_user`@`localhost` |
| GRANT SELECT ON `polytechnic_db`.`student` TO `office_user`@`localhost` |

_(মোট 2টি row)_

REVOKE-এর পরে শুধু SELECT অনুমতি রয়ে গেছে।

### Role

**Role:** **কতগুলো Privilege-এর একটি নামযুক্ত গুচ্ছ।** প্রত্যেক User-কে আলাদা আলাদা অনুমতি না দিয়ে Role তৈরি করে তা User-কে দেওয়া হয়।

```text
CREATE ROLE 'exam_controller';
GRANT SELECT, INSERT, UPDATE ON polytechnic_db.enrollment TO 'exam_controller';
GRANT 'exam_controller' TO 'office_user'@'localhost';
```

### View দিয়ে নিরাপত্তা

শিক্ষকদের বেতন গোপন রেখে শুধু নাম ও বিভাগ দেখানোর View বানিয়ে সেই View-তে অনুমতি দেওয়া যায়। তখন মূল Table-এ কোনো অনুমতি লাগে না।

```text
CREATE VIEW teacher_public AS SELECT name, dept_id FROM teacher;
GRANT SELECT ON polytechnic_db.teacher_public TO 'office_user'@'localhost';
```

```sql
DROP USER 'office_user'@'localhost';
```

## Encryption (এনক্রিপশন)

**Encryption:** **সাধারণ পাঠযোগ্য Data (Plain Text)-কে একটি Key ও Algorithm ব্যবহার করে দুর্বোধ্য রূপে (Cipher Text) রূপান্তর করা**, যাতে Key ছাড়া কেউ পড়তে না পারে। উল্টো প্রক্রিয়াকে **Decryption** বলে।

```text
Plain Text  --[Encryption + Key]-->  Cipher Text  --[Decryption + Key]-->  Plain Text
"Rahim"                              "X9#kq@..."                           "Rahim"
```

**Database-এ Encryption-এর গুরুত্ব:**

1. Hard Disk বা Backup চুরি হলেও Data পড়া যায় না।
2. Network দিয়ে যাওয়ার সময় কেউ মাঝপথে (Eavesdropping) পড়তে পারে না।
3. Password কখনো সাধারণ লেখায় রাখা হয় না, তাই DBA-ও দেখতে পান না।
4. গোপনীয়তা আইন মেনে চলা।

**Encryption কৌশল (Techniques):**

| কৌশল | বর্ণনা | উদাহরণ |
|---|---|---|
| **Symmetric Key (Private Key)** | Encryption ও Decryption-এ **একই Key** | DES, 3DES, **AES** |
| **Asymmetric Key (Public Key)** | দুটি Key: **Public Key** দিয়ে Encrypt, **Private Key** দিয়ে Decrypt | **RSA** |
| **Hashing (একমুখী)** | মূল লেখা ফেরত আনা যায় না; Password সংরক্ষণে ব্যবহার | SHA-256, bcrypt |
| **Substitution Cipher** | প্রতিটি অক্ষর অন্য অক্ষর দিয়ে প্রতিস্থাপন (প্রাচীন, দুর্বল) | Caesar Cipher: A→D, B→E |

**MySQL-এ উদাহরণ:**

```sql
SELECT
    SHA2('Office@2026', 256)                                   AS password_hash,
    HEX(AES_ENCRYPT('01711111111', 'secret_key'))              AS encrypted_phone,
    CAST(AES_DECRYPT(AES_ENCRYPT('01711111111', 'secret_key'), 'secret_key') AS CHAR) AS decrypted_phone;
```

**Output:**

| password_hash | encrypted_phone | decrypted_phone |
|---|---|---|
| 1fe9eed01482b5c8fa5fefcc9d9ad4a3048903e99a5225605d9c8065bccdc3f2 | 1E3B6DAF48A28E7C009F61769FDEBCF0 | 01711111111 |

_(মোট 1টি row)_

- `SHA2(...)`: Password-এর Hash। একই Password সবসময় একই Hash দেয়, কিন্তু Hash থেকে Password বের করা যায় না। Login-এর সময় নতুন Hash বানিয়ে তুলনা করা হয়।
- `AES_ENCRYPT/AES_DECRYPT`: Symmetric Encryption। Key জানলে আবার মূল Data পাওয়া যায়।

## SQL Injection (বাড়তি জ্ঞান)

**SQL Injection:** Login Form বা Input-এ ক্ষতিকর SQL কোড ঢুকিয়ে Database-এ অবৈধ প্রবেশের আক্রমণ।

```text
-- দুর্বল কোড (Input সরাসরি Query-তে জোড়া হচ্ছে)
query = "SELECT * FROM users WHERE name = '" + input + "'";

-- আক্রমণকারী input দিলেন:   ' OR '1'='1
-- Query হয়ে গেল:  SELECT * FROM users WHERE name = '' OR '1'='1'   → সব User বেরিয়ে আসে!
```

**প্রতিরোধ:** Prepared Statement/Parameterized Query ব্যবহার, Input যাচাই, ন্যূনতম Privilege দেওয়া।

## মনে রাখার টিপস

- **Integrity = Data সঠিক কিনা। Security = Data নিরাপদ কিনা।**
- Authentication = "কে?"; Authorization = "কী পারবে?"।
- **GRANT দেয়, REVOKE ফিরিয়ে নেয়।**
- Symmetric = এক চাবি; Asymmetric = দুই চাবি (Public + Private)।

## অধ্যায় ৬: প্রশ্নোত্তর

**অতিসংক্ষিপ্ত প্রশ্ন ও উত্তর**

1. **Database Integrity কী?** Data-র নির্ভুলতা ও সামঞ্জস্যতা বজায় রাখা।
2. **Integrity Constraint কী?** ভুল Data ঢোকা আটকানোর নিয়ম।
3. **Referential Integrity কী?** Foreign Key-র মান অবশ্যই Parent Table-এ থাকতে হবে।
4. **Trigger কী?** নির্দিষ্ট ঘটনায় স্বয়ংক্রিয়ভাবে চালু হওয়া Stored Program।
5. **Encryption কী?** Data-কে Key দিয়ে দুর্বোধ্য রূপে রূপান্তর।
6. **Database Authorization-এর স্তরগুলো কী কী?** Read, Insert, Update, Delete এবং Index, Resource, Alteration, Drop।
7. **GRANT ও REVOKE কোন ভাষার অংশ?** DCL।
8. **Role কী?** Privilege-এর নামযুক্ত গুচ্ছ।
9. **Authentication ও Authorization-এর পার্থক্য কী?** Authentication পরিচয় যাচাই করে; Authorization অনুমতি নির্ধারণ করে।
10. **AES কোন ধরনের Encryption?** Symmetric Key।

**সংক্ষিপ্ত ও রচনামূলক প্রশ্ন**

1. Database Security-র প্রয়োজনীয়তা লেখ।
2. বিভিন্ন Integrity Constraint উদাহরণসহ বর্ণনা কর।
3. Trigger কী? একটি Trigger-এর উদাহরণ দাও।
4. Database-এর Data Security-র বর্ণনা দাও (Security-র স্তর)।
5. Database-এ Encryption-এর গুরুত্ব আলোচনা কর।
6. Encryption Technique সম্পর্কে লেখ।
7. GRANT ও REVOKE Command উদাহরণসহ ব্যাখ্যা কর।

## খারাপ Design-এর সমস্যা: Redundancy ও Anomaly

ধরুন পলিটেকনিকের সব তথ্য একটি মাত্র বড় Table-এ রাখা হলো:

**result_sheet (খারাপ Design)**

| roll | name | dept_name | dept_head | course_code | course_title | marks |
|---|---|---|---|---|---|---|
| 101 | Rahim | Computer | Mr. Alam | 28561 | DBMS | 82 |
| 101 | Rahim | Computer | Mr. Alam | 28562 | Networking | 75 |
| 102 | Karim | Computer | Mr. Alam | 28561 | DBMS | 64 |
| 104 | Sumon | Civil | Mr. Kabir | 26461 | Structural Mechanics | 58 |

**Redundancy (পুনরাবৃত্তি):** "Rahim", "Computer", "Mr. Alam", "DBMS" বারবার লেখা হয়েছে।

**Anomaly (অসংগতি):** Redundancy-র কারণে তিন ধরনের সমস্যা হয়:

1. **Insertion Anomaly:** নতুন বিভাগ "Mechanical" খোলা হলো, কিন্তু এখনো কোনো ছাত্র ভর্তি হয়নি। তাহলে বিভাগের তথ্য রাখা যায় না, কারণ roll (Key-এর অংশ) NULL হতে পারে না।
2. **Deletion Anomaly:** Sumon (104) চলে গেলে তার Row মুছলে Civil বিভাগ আর Mr. Kabir-এর তথ্যও হারিয়ে যায়।
3. **Update Anomaly:** Computer বিভাগের প্রধান বদলালে প্রতিটি Row-এ বদলাতে হবে। একটি Row-ও বাদ পড়লে Data Inconsistent হয়ে যায়।

**সমাধান:** Table-কে নিয়ম মেনে ছোট ছোট Table-এ ভাগ করা। একেই **Normalization** বলে।

## Functional Dependency (FD)

**Functional Dependency:** **কোনো Relation-এ Attribute X-এর মান জানলে যদি Attribute Y-এর মান নিশ্চিতভাবে (একটিমাত্র) জানা যায়, তাহলে বলা হয় Y, X-এর ওপর Functionally Dependent।** লেখা হয় **X → Y** ("X determines Y")।

- X = **Determinant**, Y = **Dependent**।
- উদাহরণ: `roll → name` (রোল জানলে নাম নির্দিষ্ট)। কিন্তু `name → roll` নয়, কারণ দুজনের নাম এক হতে পারে।

**উপরের Table-এর FD:**

- roll → name, dept_name
- dept_name → dept_head
- course_code → course_title
- (roll, course_code) → marks

### Functional Dependency-র প্রকারভেদ

| প্রকার | অর্থ | উদাহরণ |
|---|---|---|
| **Trivial FD** | Y, X-এরই অংশ (Y ⊆ X) | (roll, name) → name |
| **Non-trivial FD** | Y, X-এর অংশ নয় | roll → name |
| **Full FD** | Y পুরো X-এর ওপর নির্ভরশীল, X-এর কোনো অংশের ওপর নয় | (roll, course_code) → marks |
| **Partial FD** | Y, Composite Key-এর **একটি অংশের** ওপর নির্ভরশীল | (roll, course_code) → name, কারণ শুধু roll → name |
| **Transitive FD** | X → Y এবং Y → Z, তাহলে X → Z (পরোক্ষ নির্ভরতা) | roll → dept_name, dept_name → dept_head, তাই roll → dept_head |

### Armstrong's Axioms (FD-র নিয়ম)

1. **Reflexivity:** Y ⊆ X হলে X → Y।
2. **Augmentation:** X → Y হলে XZ → YZ।
3. **Transitivity:** X → Y এবং Y → Z হলে X → Z।

এই তিনটি থেকে আরও নিয়ম পাওয়া যায়: **Union** (X → Y, X → Z হলে X → YZ), **Decomposition** (X → YZ হলে X → Y ও X → Z), **Pseudo-transitivity**।

## Decomposition

**Decomposition:** একটি Relation-কে দুই বা ততোধিক ছোট Relation-এ ভাগ করা।

**ভালো Decomposition-এর দুটি শর্ত:**

1. **Lossless Join:** ভাগ করা Table-গুলো আবার JOIN করলে **হুবহু মূল Table** পাওয়া যাবে। কোনো তথ্য হারাবে না, ভুয়া Row-ও আসবে না। শর্ত: ভাগ দুটির সাধারণ Attribute অন্তত একটি ভাগের Key হতে হবে।
2. **Dependency Preservation:** মূল Table-এর সব FD ভাগ করা Table-গুলোতেও যাচাই করা যাবে।

## Normalization

**Normalization:** **Functional Dependency ও Key-এর ভিত্তিতে একটি বড় Relation-কে ধাপে ধাপে (Normal Form অনুযায়ী) ছোট, সুগঠিত Relation-এ ভাগ করার প্রক্রিয়া, যাতে Data Redundancy ও Anomaly দূর হয়।** 1970-এর দশকে **E. F. Codd** এর ধারণা দেন।

**Normalization-এর প্রয়োজনীয়তা:**

1. Data Redundancy কমানো।
2. Insertion, Deletion ও Update Anomaly দূর করা।
3. Data Consistency ও Integrity নিশ্চিত করা।
4. Storage-এর জায়গা বাঁচানো।
5. Database-এর কাঠামো সহজ, পরিষ্কার ও রক্ষণাবেক্ষণযোগ্য করা।

**Normal Form-এর ধাপ (Stages/Rules):** 1NF → 2NF → 3NF → BCNF → 4NF → 5NF। বাস্তবে সাধারণত **3NF বা BCNF** পর্যন্ত করাই যথেষ্ট। প্রতিটি উচ্চতর Normal Form আগেরটির সব শর্ত পূরণ করে।

### Unnormalized Form (UNF)

যেখানে একটি ঘরে একাধিক মান (Repeating Group) থাকে:

| roll | name | dept_name | dept_head | courses (code-title-marks) |
|---|---|---|---|---|
| 101 | Rahim | Computer | Mr. Alam | 28561-DBMS-82, 28562-Networking-75 |
| 102 | Karim | Computer | Mr. Alam | 28561-DBMS-64 |

### First Normal Form (1NF)

**নিয়ম:** **প্রতিটি ঘরে একটিমাত্র (Atomic) মান থাকবে; কোনো Repeating Group বা Multivalued Attribute থাকবে না; প্রতিটি Row অনন্য হবে।**

**করণীয়:** একাধিক মানকে আলাদা Row-তে ভাঙা।

| roll | name | dept_name | dept_head | course_code | course_title | marks |
|---|---|---|---|---|---|---|
| 101 | Rahim | Computer | Mr. Alam | 28561 | DBMS | 82 |
| 101 | Rahim | Computer | Mr. Alam | 28562 | Networking | 75 |
| 102 | Karim | Computer | Mr. Alam | 28561 | DBMS | 64 |

Primary Key = **(roll, course_code)**। এখন 1NF, কিন্তু Redundancy এখনো আছে।

### Second Normal Form (2NF)

**নিয়ম:** **Relation 1NF-এ থাকবে এবং কোনো Non-key Attribute Primary Key-এর অংশবিশেষের ওপর নির্ভরশীল (Partial Dependency) হবে না।** অর্থাৎ প্রতিটি Non-key Attribute পুরো Key-এর ওপর **Fully** নির্ভরশীল হবে।

**সমস্যা:** Key = (roll, course_code), কিন্তু:

- name, dept_name, dept_head শুধু **roll**-এর ওপর নির্ভরশীল (Partial)।
- course_title শুধু **course_code**-এর ওপর নির্ভরশীল (Partial)।

**করণীয়:** Partial Dependency আলাদা Table-এ সরানো।

**student_2nf** (Key: roll)

| roll | name | dept_name | dept_head |
|---|---|---|---|
| 101 | Rahim | Computer | Mr. Alam |
| 102 | Karim | Computer | Mr. Alam |

**course** (Key: course_code)

| course_code | course_title |
|---|---|
| 28561 | DBMS |
| 28562 | Networking |

**enrollment** (Key: roll, course_code)

| roll | course_code | marks |
|---|---|---|
| 101 | 28561 | 82 |
| 101 | 28562 | 75 |
| 102 | 28561 | 64 |

> **মনে রাখুন:** Primary Key যদি একটিমাত্র Attribute হয় (Composite না হয়), তাহলে 1NF-এ থাকা Relation স্বয়ংক্রিয়ভাবে 2NF-এ থাকে।

### Third Normal Form (3NF)

**নিয়ম:** **Relation 2NF-এ থাকবে এবং কোনো Non-key Attribute অন্য একটি Non-key Attribute-এর ওপর নির্ভরশীল (Transitive Dependency) হবে না।**

**সমস্যা:** student_2nf-এ roll → dept_name → dept_head। এখানে dept_head, Key-এর ওপর **পরোক্ষভাবে** (dept_name-এর মাধ্যমে) নির্ভরশীল। বিভাগের প্রধান বদলালে সব ছাত্রের Row বদলাতে হবে (Update Anomaly)।

**করণীয়:** Transitive অংশটি আলাদা Table-এ সরানো।

**student** (Key: roll)

| roll | name | dept_name |
|---|---|---|
| 101 | Rahim | Computer |
| 102 | Karim | Computer |

**department** (Key: dept_name)

| dept_name | dept_head |
|---|---|
| Computer | Mr. Alam |
| Civil | Mr. Kabir |

এখন চারটি Table: student, department, course, enrollment। প্রতিটি তথ্য **একবারই** আছে। বিভাগের প্রধান বদলাতে একটি Row বদলালেই চলবে। ছাত্র ছাড়াও নতুন বিভাগ যোগ করা যাবে। আমাদের `polytechnic_db` ঠিক এভাবেই সাজানো।

### Boyce-Codd Normal Form (BCNF)

**নিয়ম:** **প্রতিটি Non-trivial Functional Dependency X → Y-এর ক্ষেত্রে X অবশ্যই একটি Super Key হবে।** এটি 3NF-এর চেয়ে কঠোর রূপ (তাই একে 3.5NF-ও বলে)।

**উদাহরণ:** teaching(student, subject, teacher)। নিয়ম: প্রতিটি শিক্ষক একটিমাত্র বিষয় পড়ান (teacher → subject), আর একজন ছাত্র একটি বিষয় একজন শিক্ষকের কাছেই পড়ে।

| student | subject | teacher |
|---|---|---|
| Rahim | DBMS | Mr. Alam |
| Karim | DBMS | Ms. Nasrin |
| Rahim | Java | Mr. Rafiq |

Candidate Key দুটি: (student, subject) এবং (student, teacher)। কিন্তু **teacher → subject**, আর teacher একা Super Key নয়। subject একটি Candidate Key-এর অংশ (Prime Attribute), তাই Relation-টি 3NF-এ আছে, কিন্তু BCNF-এ নেই। সমস্যা: Mr. Alam-এর বিষয় বদলালে একাধিক Row বদলাতে হবে।

**করণীয়:** teacher_subject(teacher, subject) আর student_teacher(student, teacher)-এ ভাগ করা।

### 4NF ও 5NF (পরিচিতি)

- **Fourth Normal Form (4NF):** BCNF + কোনো **Multivalued Dependency (MVD)** থাকবে না। যেমন একজন শিক্ষকের একাধিক বিষয় আর একাধিক শখ একই Table-এ রাখলে অপ্রয়োজনীয় সব জোড়া তৈরি হয়। আলাদা Table করতে হয়।
- **Fifth Normal Form (5NF / PJNF):** 4NF + কোনো **Join Dependency** থাকবে না। Table-কে আরও ভাঙলে আর Lossless থাকবে না, এমন অবস্থা।

### Normal Form সারসংক্ষেপ

| Normal Form | শর্ত | যা দূর হয় |
|---|---|---|
| 1NF | Atomic মান, Repeating Group নেই | Multivalued/Repeating Group |
| 2NF | 1NF + Partial Dependency নেই | Composite Key-এর অংশের ওপর নির্ভরতা |
| 3NF | 2NF + Transitive Dependency নেই | Non-key → Non-key নির্ভরতা |
| BCNF | প্রতিটি Determinant একটি Super Key | Non-key Determinant |
| 4NF | BCNF + Multivalued Dependency নেই | স্বাধীন বহুমানের সমস্যা |
| 5NF | 4NF + Join Dependency নেই | জটিল Join সমস্যা |

**Normalization-এর অসুবিধা:** Table সংখ্যা বাড়ে, তাই Query-তে বেশি JOIN লাগে, আর অনেক সময় Query ধীর হয়। তাই Report-এর মতো কাজে কখনো কখনো ইচ্ছা করে কিছু Redundancy রাখা হয়। একে **Denormalization** বলে।

## সামগ্রিক Database Design প্রক্রিয়া

1. **Requirement Analysis (প্রয়োজন বিশ্লেষণ):** ব্যবহারকারীদের সঙ্গে কথা বলে জানা কোন তথ্য রাখতে হবে, কোন Report লাগবে। যেমন অধ্যক্ষ, শিক্ষক, পরীক্ষা নিয়ন্ত্রকের চাহিদা।
2. **Conceptual Design:** E-R Diagram আঁকা (Entity, Attribute, Relationship)।
3. **Logical Design:** E-R Diagram থেকে Table (Relation Schema) তৈরি, Key নির্ধারণ।
4. **Normalization:** FD খুঁজে 3NF/BCNF পর্যন্ত Normalize করা।
5. **Physical Design:** DBMS বাছাই (MySQL/Oracle), Data Type, Index, Storage নির্ধারণ।
6. **Implementation:** SQL দিয়ে Database তৈরি, Data লোড।
7. **Testing ও Evaluation:** সঠিকতা ও গতি পরীক্ষা।
8. **Maintenance:** Backup, Performance Tuning, প্রয়োজনে পরিবর্তন।

```text
Requirement → E-R Diagram → Tables → Normalization → Physical Design → Implementation → Testing → Maintenance
```

## মনে রাখার টিপস

- **"The Key, the whole Key, and nothing but the Key, so help me Codd."**
  - 1NF: **Key** আছে (Atomic মান)।
  - 2NF: **পুরো Key**-এর ওপর নির্ভরশীল (Partial নয়)।
  - 3NF: **শুধু Key**-এর ওপর নির্ভরশীল (Transitive নয়)।
- Partial = Composite Key-এর অংশ; Transitive = Non-key-এর মাধ্যমে।
- Anomaly তিনটি: **Insert, Delete, Update (IDU)।**

## অধ্যায় ৭: প্রশ্নোত্তর

**অতিসংক্ষিপ্ত প্রশ্ন ও উত্তর**

1. **Normalization কাকে বলে?** FD-র ভিত্তিতে বড় Relation ভেঙে Redundancy ও Anomaly দূর করার প্রক্রিয়া।
2. **Normalization-এর Stage/Rule কয়টি?** প্রধানত ৬টি: 1NF, 2NF, 3NF, BCNF, 4NF, 5NF।
3. **RDBMS-এ Redundancy কী?** একই Data-র অপ্রয়োজনীয় পুনরাবৃত্তি।
4. **Functional Dependency কী?** X-এর মান জানলে Y-এর মান নির্দিষ্টভাবে জানা গেলে X → Y।
5. **Partial Dependency কী?** Non-key Attribute-এর Composite Key-এর অংশের ওপর নির্ভরতা।
6. **Transitive Dependency কী?** X → Y, Y → Z থেকে আসা X → Z (পরোক্ষ নির্ভরতা)।
7. **Anomaly কত প্রকার?** তিন প্রকার: Insertion, Deletion, Update।
8. **Lossless Join Decomposition কী?** ভাগ করা Table JOIN করলে হুবহু মূল Table পাওয়া যায় এমন ভাগ।
9. **BCNF-এর শর্ত কী?** প্রতিটি Non-trivial FD-র Determinant একটি Super Key।
10. **Denormalization কী?** দ্রুততার জন্য ইচ্ছাকৃতভাবে কিছু Redundancy রাখা।

**সংক্ষিপ্ত ও রচনামূলক প্রশ্ন**

1. Normalization-এর প্রয়োজনীয়তা লেখ।
2. RDBMS-এর Normalization-এর তিনটি স্টেজ (1NF, 2NF, 3NF) উদাহরণসহ বর্ণনা কর।
3. Insertion, Deletion ও Update Anomaly উদাহরণসহ ব্যাখ্যা কর।
4. Functional Dependency-র প্রকারভেদ লেখ।
5. 3NF ও BCNF-এর পার্থক্য লেখ।
6. সামগ্রিক Database Design প্রক্রিয়া বর্ণনা কর।


# অধ্যায় ৮: ডাটা স্টোরেজ মিডিয়া

> **এক নজরে:** Physical Storage Media-র প্রকারভেদ ও Storage Hierarchy; Cache, Main Memory, Flash Memory, Magnetic Disk, Optical Disk, Magnetic Tape; Magnetic Disk-এর গঠন ও Performance; RAID ও এর Level; RAID Level নির্বাচন; Buffer ও Buffer Manager; File Organization (Fixed-length ও Variable-length Record); File-এ Record সাজানোর পদ্ধতি ও Clustering; Indexing ও Hashing পরিচিতি।

**আগের অধ্যায়ের সঙ্গে সম্পর্ক:** অধ্যায় ১-এর Physical Level ("Data কীভাবে Disk-এ থাকে") আর অধ্যায় ২-এর File Manager ও Buffer Manager-এর বিস্তারিত এই অধ্যায়ে।

## Physical Storage Media

**Physical Storage Media:** **যে Hardware মাধ্যমে Data বাস্তবে (Physically) সংরক্ষণ করা হয়।** যেমন RAM, Hard Disk, SSD, DVD, Tape।

**Storage Media-র শ্রেণিবিভাগ:**

1. **Volatile বনাম Non-volatile:**
   - **Volatile:** বিদ্যুৎ চলে গেলে Data মুছে যায় (Cache, RAM)।
   - **Non-volatile:** বিদ্যুৎ না থাকলেও Data থাকে (Flash, Hard Disk, DVD, Tape)।
2. **Primary, Secondary ও Tertiary:**
   - **Primary Storage:** CPU সরাসরি ব্যবহার করে; দ্রুত, Volatile (Cache, Main Memory)।
   - **Secondary (Online) Storage:** দীর্ঘমেয়াদি, Non-volatile, তুলনামূলক দ্রুত (Flash, Magnetic Disk)।
   - **Tertiary (Offline) Storage:** Archive ও Backup-এর জন্য; ধীর, সস্তা, বিশাল (Optical Disk, Magnetic Tape)।

### বিভিন্ন Storage Media-র বৈশিষ্ট্য

| Media | বৈশিষ্ট্য | গতি | খরচ/Byte | Volatile? |

| **Flash Memory** | Pen drive, SSD, Memory Card। বিদ্যুৎ ছাড়াও Data থাকে। পড়া দ্রুত, লেখা তুলনামূলক ধীর। একটি জায়গায় সীমিত বার মুছে লেখা যায় (Erase cycle)। NOR ও NAND দুই ধরন | দ্রুত | মাঝারি | না |

| **Optical Disk** | CD (700MB), DVD (4.7GB), Blu-ray (25GB+); Laser দিয়ে পড়া; বিতরণ ও Archive | ধীর | কম | না |
| **Magnetic Tape** | Sequential Access (শুরু থেকে পড়তে হয়); Backup ও Archive; বিশাল ধারণক্ষমতা | সবচেয়ে ধীর | সবচেয়ে কম | না |

**Flash Memory (সংজ্ঞা):** **একটি Non-volatile, Electrically Erasable ও Programmable Semiconductor Memory, যাতে বিদ্যুৎ সরবরাহ বন্ধ থাকলেও Data সংরক্ষিত থাকে।** যেমন SSD, Pen drive, মোবাইলের Storage।

## Magnetic Disk-এর গঠন ও Performance

**গঠন:**

- **Platter:** চৌম্বকীয় প্রলেপযুক্ত ঘূর্ণায়মান চাকতি (5400/7200 RPM)।
- **Track:** Platter-এর ওপর এককেন্দ্রিক বৃত্তাকার পথ।
- **Sector:** Track-এর ক্ষুদ্রতম অংশ (সাধারণত 512 Byte বা 4 KB), Data পড়া-লেখার একক।
- **Cylinder:** সব Platter-এর একই অবস্থানের Track-গুলোর সমষ্টি।
- **Read-Write Head ও Arm:** Data পড়া-লেখার যন্ত্র, Arm দিয়ে নির্দিষ্ট Track-এ সরে।
- **Disk Controller:** Computer আর Disk-এর মধ্যে সংযোগ, Error যাচাই (Checksum)।

**Performance Measure:**

1. **Access Time = Seek Time + Rotational Latency।**
   - **Seek Time:** Head-কে সঠিক Track-এ নিতে যে সময় লাগে।
   - **Rotational Latency:** সঠিক Sector Head-এর নিচে ঘুরে আসতে যে সময় লাগে।
2. **Data Transfer Rate:** প্রতি সেকেন্ডে কত Data পড়া/লেখা যায় (MB/s)।
3. **MTTF (Mean Time To Failure):** গড়ে কতক্ষণ ব্যর্থ না হয়ে চলবে, অর্থাৎ নির্ভরযোগ্যতা।

## RAID

**RAID (Redundant Array of Independent Disks):** **একাধিক Disk একসঙ্গে ব্যবহার করে সেগুলোকে একটি বড় Disk হিসেবে কাজ করানোর পদ্ধতি**, যাতে (১) **নির্ভরযোগ্যতা (Reliability)** আর (২) **গতি (Performance)** দুটোই বাড়ে।

**দুটি মূল কৌশল:**

- **Redundancy (Mirroring):** একই Data দুটি Disk-এ রাখা। একটি নষ্ট হলে অন্যটি থেকে পাওয়া যায়। নির্ভরযোগ্যতা বাড়ে।
- **Striping (Parallelism):** Data টুকরো করে একাধিক Disk-এ ছড়িয়ে রাখা, যাতে একসঙ্গে সব Disk থেকে পড়া যায়। গতি বাড়ে।
- **Parity:** Error Correction তথ্য (XOR), যা দিয়ে একটি নষ্ট Disk-এর Data পুনর্গঠন করা যায়।

### RAID Level

| Level | পদ্ধতি | ন্যূনতম Disk | সুবিধা | অসুবিধা |
|---|---|---|---|---|
| **RAID 0** | Block Striping, কোনো Redundancy নেই | 2 | সবচেয়ে দ্রুত, পুরো জায়গা ব্যবহার | একটি Disk নষ্ট হলে সব Data নষ্ট |
| **RAID 1** | Mirroring (হুবহু কপি) | 2 | উচ্চ নির্ভরযোগ্যতা, দ্রুত Read | অর্ধেক জায়গা নষ্ট (খরচ দ্বিগুণ) |
| **RAID 2** | Bit Striping + Hamming Code (ECC) | অনেক | Error সংশোধন | জটিল, এখন ব্যবহার হয় না |
| **RAID 3** | Byte/Bit Striping + একটি Parity Disk | 3 | বড় File-এর জন্য দ্রুত | একসঙ্গে একটি মাত্র কাজ |
| **RAID 4** | Block Striping + একটি আলাদা Parity Disk | 3 | Read দ্রুত | Parity Disk-এ চাপ (Bottleneck) |
| **RAID 5** | Block Striping + Parity **সব Disk-এ ছড়ানো** | 3 | গতি, নির্ভরযোগ্যতা ও জায়গার ভালো ভারসাম্য; **সবচেয়ে প্রচলিত** | Write তুলনামূলক ধীর |
| **RAID 6** | RAID 5 + দ্বিতীয় Parity (P+Q) | 4 | একসঙ্গে **দুটি** Disk নষ্ট হলেও Data থাকে | Write আরও ধীর |
| **RAID 10 (1+0)** | Mirroring + Striping | 4 | দ্রুত ও নির্ভরযোগ্য | খরচ বেশি |

### RAID Level নির্বাচনের পদ্ধতি

RAID Level বাছাইয়ের সময় যা বিবেচনা করতে হয়:

1. **খরচ:** অতিরিক্ত Disk-এর দাম (RAID 1-এ দ্বিগুণ)।
2. **Performance চাহিদা:** কত I/O Operation প্রতি সেকেন্ডে লাগবে; Read বেশি না Write বেশি।
3. **Disk নষ্ট হলে Performance:** নষ্ট অবস্থায় System কতটা চলবে।
4. **Rebuild Time:** নষ্ট Disk-এর Data পুনর্গঠনে কত সময় লাগবে।

**সাধারণ নির্দেশনা:**

- Data হারালে সমস্যা নেই, শুধু গতি দরকার → **RAID 0** (যেমন অস্থায়ী কাজ)।
- **Write বেশি**, উচ্চ নির্ভরযোগ্যতা দরকার (ব্যাংকের Transaction Log) → **RAID 1 বা RAID 10**।
- **Read বেশি**, কম খরচে নির্ভরযোগ্যতা (বড় Database, File Server) → **RAID 5**।
- খুব বড় Disk, একসঙ্গে দুটি Disk নষ্ট হওয়ার ঝুঁকি → **RAID 6**।

## Buffer ও Buffer Manager

**Buffer:** **Main Memory-র যে অংশে Disk Block-এর কপি সাময়িকভাবে রাখা হয়।** Disk থেকে বারবার পড়ার চেয়ে Memory থেকে পড়া হাজার গুণ দ্রুত।

**Buffer Manager:** DBMS-এর যে অংশ Buffer-এর জায়গা বরাদ্দ করে। কোনো Block দরকার হলে প্রথমে Buffer-এ খোঁজে; না পেলে Disk থেকে আনে। জায়গা না থাকলে কোনো Block সরিয়ে (প্রয়োজনে Disk-এ লিখে) জায়গা করে।

**Buffer Replacement Policy:**

- **LRU (Least Recently Used):** সবচেয়ে আগে ব্যবহৃত Block সরানো।
- **MRU (Most Recently Used):** সবচেয়ে সম্প্রতি ব্যবহৃত Block সরানো (কিছু Join Operation-এ কাজের)।
- **Pinned Block:** যে Block এখন ব্যবহৃত হচ্ছে, তা সরানো নিষেধ।
- **Forced Output:** Recovery-র জন্য Block জোর করে Disk-এ লেখা।

## File Organization (ফাইল সংগঠন)

Database অনেকগুলো File হিসেবে Disk-এ থাকে। প্রতিটি File হলো Record-এর ধারাবাহিক সংগ্রহ, আর Disk-এ তা **Block** আকারে থাকে।

### Fixed-length Record

প্রতিটি Record-এর দৈর্ঘ্য সমান। যেমন:

```text
student_record:  roll CHAR(5), name CHAR(20), cgpa CHAR(4)   → প্রতিটি Record = 29 Byte
Record i শুরু হবে Byte = 29 × (i − 1) থেকে
```

**সুবিধা:** গঠন সহজ; Record i-এর অবস্থান সরাসরি হিসাব করা যায়।

**মোছার সমস্যা ও সমাধান:** মাঝখানের একটি Record মুছলে ফাঁকা জায়গা তৈরি হয়।

1. পরের সব Record এক ঘর করে সরিয়ে আনা (ধীর)।
2. শেষ Record-টি ফাঁকা জায়গায় এনে বসানো।
3. **Free List:** ফাঁকা জায়গাগুলোকে একটি Linked List-এ রাখা। File Header-এ প্রথম ফাঁকা জায়গার ঠিকানা থাকে। নতুন Record সেখানে বসানো হয় (সবচেয়ে ভালো পদ্ধতি)।

### Variable-length Record

Record-এর দৈর্ঘ্য আলাদা আলাদা হতে পারে। কারণ: VARCHAR Field; একাধিক Record Type একই File-এ; Repeating Field।

**সংরক্ষণ পদ্ধতি:** **Slotted Page Structure।** প্রতিটি Block-এর শুরুতে একটি Header থাকে, যেখানে Record-এর সংখ্যা, Free Space কোথায় শেষ, আর প্রতিটি Record-এর অবস্থান ও আকার লেখা থাকে। Record-গুলো Block-এর শেষ দিক থেকে জমা হয়।

### Fixed-length ও Variable-length Record-এর পার্থক্য

| বিষয় | Fixed-length Record | Variable-length Record |
|---|---|---|
| দৈর্ঘ্য | সব Record সমান | Record ভেদে আলাদা |
| Data Type | CHAR, INT | VARCHAR, TEXT |
| Record খোঁজা | সহজ (সরাসরি হিসাব) | Header/Slot দেখে খুঁজতে হয় |
| জায়গার ব্যবহার | অপচয় হতে পারে (ছোট নামেও পুরো 20 Byte) | দক্ষ |
| মোছার পরে জায়গা পূরণ | সহজ (একই আকারের Record বসে) | জটিল (Fragmentation) |
| বাস্তবায়ন | সহজ | জটিল (Slotted Page) |

### File-এ Record সাজানোর পদ্ধতি (Organization of Records)

1. **Heap File Organization:** যেখানে জায়গা পাওয়া যায়, সেখানে Record রাখা। কোনো ক্রম নেই। Insert দ্রুত, খোঁজা ধীর।
2. **Sequential File Organization:** একটি **Search Key** (যেমন roll) অনুযায়ী সাজানো। ক্রম অনুযায়ী পড়া দ্রুত।
3. **Hashing File Organization:** একটি **Hash Function** দিয়ে হিসাব করে ঠিক হয় Record কোন Block (Bucket)-এ যাবে। নির্দিষ্ট মান খোঁজা খুব দ্রুত।
4. **Multitable Clustering File Organization:** একাধিক Table-এর সম্পর্কিত Record **একই Block-এ পাশাপাশি** রাখা।

**Clustering (সংজ্ঞা):** **যেসব Record প্রায়ই একসঙ্গে ব্যবহৃত হয়, সেগুলোকে Disk-এর একই বা কাছাকাছি Block-এ রাখা**, যাতে কম Disk Access-এ সব পাওয়া যায়।

> **উদাহরণ:** Computer বিভাগের তথ্য আর সেই বিভাগের সব ছাত্রের Record একই Block-এ রাখলে "Computer বিভাগের ছাত্রদের তালিকা" Query খুব দ্রুত চলে। তবে শুধু সব বিভাগের তালিকা চাইলে বেশি Block পড়তে হয়।

## Indexing ও Hashing (পরিচিতি)

**Index:** বইয়ের সূচিপত্রের মতো। প্রতিটি Index Entry-তে থাকে **Search Key** আর Record-এর **Pointer (ঠিকানা)**।

| Index-এর ধরন | অর্থ |
|---|---|
| **Primary (Clustering) Index** | File যে Search Key অনুযায়ী সাজানো, সেই Key-এর Index |
| **Secondary (Non-clustering) Index** | অন্য কোনো Column-এর Index (File সেই ক্রমে সাজানো নয়) |
| **Dense Index** | প্রতিটি Search Key মানের জন্য একটি Entry |
| **Sparse Index** | কিছু মানের জন্য Entry (যেমন প্রতিটি Block-এর প্রথম Record-এর জন্য) |
| **Multilevel Index** | Index বড় হলে Index-এর ওপর আবার Index |
| **B+ Tree Index** | Balanced Tree; সব Leaf একই উচ্চতায়; Insert/Delete-এর পরও নিজে ভারসাম্য রাখে; MySQL-এর ডিফল্ট Index |

**Hashing:** Hash Function h(K) দিয়ে Search Key থেকে সরাসরি Bucket-এর ঠিকানা বের করা। যেমন h(roll) = roll mod 10। নির্দিষ্ট মান খোঁজায় (=) খুব দ্রুত, কিন্তু Range খোঁজায় (BETWEEN) উপযোগী নয়।

## মনে রাখার টিপস

- Hierarchy-তে **ওপরে = দ্রুত, দামি, ছোট, Volatile; নিচে = ধীর, সস্তা, বড়, Non-volatile।**
- **RAID 0 = গতি (Striping), RAID 1 = নিরাপত্তা (Mirroring), RAID 5 = দুটোর ভারসাম্য (Parity ছড়ানো)।**
- Access Time = Seek + Rotational Latency।

## অধ্যায় ৮: প্রশ্নোত্তর

**অতিসংক্ষিপ্ত প্রশ্ন ও উত্তর**

1. **RAID কী?** একাধিক Disk একসঙ্গে ব্যবহার করে নির্ভরযোগ্যতা ও গতি বাড়ানোর পদ্ধতি।
2. **Physical Storage Media কী?** যে Hardware-এ Data বাস্তবে সংরক্ষিত হয়।
3. **Flash Memory কী?** Non-volatile, বৈদ্যুতিকভাবে মুছে লেখা যায় এমন Semiconductor Memory।
4. **Buffer কী?** Disk Block-এর কপি রাখার Main Memory-র অংশ।
5. **Clustering কী?** একসঙ্গে ব্যবহৃত Record-গুলো একই Block-এ রাখা।
6. **Physical Storage Media-র তালিকা দাও।** Cache, Main Memory, Flash Memory, Magnetic Disk, Optical Disk, Magnetic Tape।
7. **Volatile Storage কী?** বিদ্যুৎ চলে গেলে যার Data মুছে যায়, যেমন RAM।
8. **Seek Time কী?** Head-কে সঠিক Track-এ নিতে যে সময় লাগে।
9. **Mirroring কী?** একই Data দুটি Disk-এ রাখা (RAID 1)।
10. **Striping কী?** Data টুকরো করে একাধিক Disk-এ ছড়িয়ে রাখা (RAID 0)।

**সংক্ষিপ্ত ও রচনামূলক প্রশ্ন**

1. বিভিন্ন Storage Media-র বৈশিষ্ট্য বর্ণনা কর।
2. Fixed-length ও Variable-length Record File-এর পার্থক্য লেখ।
3. Fixed-length Record File Organization ব্যাখ্যা কর।
4. RAID Level নির্বাচন করার পদ্ধতি লেখ।
5. বিভিন্ন RAID Level বর্ণনা কর।
6. Buffer Manager-এর কাজ ও Replacement Policy লেখ।
7. File-এ Record সাজানোর বিভিন্ন পদ্ধতি বর্ণনা কর।


# অধ্যায় ৯: ট্রানজেকশন এবং কনকারেন্সি কন্ট্রোল

> **এক নজরে:** Transaction কী; ACID বৈশিষ্ট্য; Transaction State; COMMIT, ROLLBACK, SAVEPOINT (MySQL-এ হাতে-কলমে); Concurrent Execution ও এর সুবিধা (Throughput); Concurrency-র সমস্যা; Schedule ও Serializability; Lock-based Protocol ও Data Locking; Two-Phase Locking; Deadlock; Timestamp Protocol; Recovery (Log, Checkpoint); Isolation Level।

**আগের অধ্যায়ের সঙ্গে সম্পর্ক:** অধ্যায় ১-এর "Atomicity Problem" আর "Concurrent Access Anomaly", এবং অধ্যায় ২-এর Transaction Manager: এই অধ্যায়ে এদের পুরো সমাধান।

## Transaction কী

**Transaction:** **Database-এর ওপর সম্পাদিত এক বা একাধিক Operation (Read/Write)-এর একটি যৌক্তিক একক (Logical Unit of Work), যা হয় সম্পূর্ণভাবে সম্পন্ন হবে, নয়তো একেবারেই হবে না।**

> **উদাহরণ:** Rahim-এর Account থেকে Karim-কে 1000 টাকা পাঠানো:

```text
T1:  read(A)          -- Rahim-এর ব্যালেন্স পড়া
     A := A − 1000
     write(A)
     read(B)          -- Karim-এর ব্যালেন্স পড়া
     B := B + 1000
     write(B)
```

`write(A)`-এর পরে কিন্তু `write(B)`-এর আগে বিদ্যুৎ চলে গেলে 1000 টাকা "হাওয়া" হয়ে যাবে! Transaction নিশ্চিত করে এমন অর্ধেক কাজ কখনো স্থায়ী হবে না।

## ACID বৈশিষ্ট্য (Transaction-এর বৈশিষ্ট্যসমূহ)

| বৈশিষ্ট্য | অর্থ | টাকা পাঠানোর উদাহরণে | কে নিশ্চিত করে |
|---|---|---|---|
| **A**tomicity (অবিভাজ্যতা) | সব Operation হবে, নয়তো একটিও না ("All or Nothing") | A থেকে কাটা আর B-তে যোগ, দুটোই হবে অথবা কোনোটাই না | Recovery Manager |
| **C**onsistency (সামঞ্জস্যতা) | Transaction-এর আগে ও পরে Database সঠিক (Consistent) অবস্থায় থাকবে | A + B-এর মোট টাকা আগে-পরে সমান | Programmer + Integrity Constraint |
| **I**solation (বিচ্ছিন্নতা) | একসঙ্গে চলা Transaction-গুলো একে অপরের অসম্পূর্ণ কাজ দেখবে না | টাকা পাঠানোর মাঝপথে অন্য কেউ ভুল মোট দেখবে না | Concurrency Control Manager |
| **D**urability (স্থায়িত্ব) | একবার COMMIT হলে System crash হলেও পরিবর্তন হারাবে না | SMS আসার পরে বিদ্যুৎ গেলেও টাকা পৌঁছে থাকবে | Recovery Manager (Log) |

## Transaction State

![Transaction State Diagram](images/transaction_states.png){width=5.5in}

1. **Active:** Transaction শুরু হয়েছে, Operation চলছে।
2. **Partially Committed:** শেষ Statement চলেছে, কিন্তু পরিবর্তন এখনো Memory-তে (স্থায়ী হয়নি)।
3. **Committed:** সফলভাবে শেষ, পরিবর্তন স্থায়ী।
4. **Failed:** কোনো Error-এর কারণে আর এগোনো সম্ভব নয়।
5. **Aborted:** Rollback করে Database-কে Transaction-এর আগের অবস্থায় ফেরানো হয়েছে। এরপর Transaction **Restart** (নতুন করে চালানো) বা **Kill** (বাতিল) করা যায়।

## MySQL-এ Transaction: হাতে-কলমে

| Command | কাজ |
|---|---|
| `START TRANSACTION` (বা `BEGIN`) | Transaction শুরু |
| `COMMIT` | সব পরিবর্তন স্থায়ী করা |
| `ROLLBACK` | সব পরিবর্তন বাতিল করে আগের অবস্থায় ফেরা |
| `SAVEPOINT name` | মাঝপথে একটি চিহ্ন রাখা |
| `ROLLBACK TO name` | শুধু ওই চিহ্ন পর্যন্ত ফেরা |

শুরুর ব্যালেন্স: Rahim (1) = 5000, Karim (2) = 2000।

**(ক) সফল Transaction (COMMIT):** Rahim থেকে Karim-কে 1000 টাকা:

```sql
START TRANSACTION;
UPDATE account SET balance = balance - 1000 WHERE acc_no = 1;
UPDATE account SET balance = balance + 1000 WHERE acc_no = 2;
COMMIT;
SELECT * FROM account;
```

**Output:**

| acc_no | holder | balance |
|---|---|---|
| 1 | Rahim | 4000 |
| 2 | Karim | 3000 |

_(মোট 2টি row)_

মোট টাকা আগেও 7000, পরেও 7000 (Consistency)।

**(খ) ROLLBACK:** ভুল করে Karim-এর ব্যালেন্স 0 করা হলো, তারপর বাতিল:

```sql
START TRANSACTION;
UPDATE account SET balance = 0 WHERE acc_no = 2;
ROLLBACK;
SELECT * FROM account;
```

**Output:**

| acc_no | holder | balance |
|---|---|---|
| 1 | Rahim | 4000 |
| 2 | Karim | 3000 |

_(মোট 2টি row)_

ROLLBACK-এর পরে Karim-এর 3000 টাকা অক্ষত।

**(গ) SAVEPOINT:** দুজনকেই 500 টাকা বোনাস দিতে গিয়ে দ্বিতীয়টি বাতিল:

```sql
START TRANSACTION;
UPDATE account SET balance = balance + 500 WHERE acc_no = 1;
SAVEPOINT after_rahim;
UPDATE account SET balance = balance + 500 WHERE acc_no = 2;
ROLLBACK TO after_rahim;
COMMIT;
SELECT * FROM account;
```

**Output:**

| acc_no | holder | balance |
|---|---|---|
| 1 | Rahim | 4500 |
| 2 | Karim | 3000 |

_(মোট 2টি row)_

শুধু Rahim-এর বোনাস স্থায়ী হয়েছে (4000 + 500 = 4500)।

**(ঘ) Constraint ভাঙলে:** Rahim-এর চেয়ে বেশি টাকা (9000) পাঠানোর চেষ্টা। `balance >= 0` CHECK ভাঙায় পুরো Statement বাতিল:

```sql
UPDATE account SET balance = balance - 9000 WHERE acc_no = 1;
```

**MySQL Error:**

```text
ERROR 3819 (HY000): Check constraint 'account_chk_1' is violated.
```

## Concurrent Execution ও Concurrency

**Concurrency:** **একাধিক Transaction একই সময়ে (পর্যায়ক্রমে মিশিয়ে) চলা।** যেমন হাজারো মানুষ একসঙ্গে bKash ব্যবহার করছেন।

**Concurrent Execution-এর সুবিধা:**

1. **Throughput বৃদ্ধি:** **নির্দিষ্ট সময়ে সম্পন্ন Transaction-এর সংখ্যা।** একটি Transaction Disk থেকে পড়ার সময় CPU অন্যটির কাজ করে, তাই বেশি কাজ হয়।
2. **CPU ও Disk-এর ভালো ব্যবহার:** কোনোটিই অলস বসে থাকে না।
3. **Average Response Time কমে:** ছোট Transaction-কে বড় Transaction-এর পেছনে অপেক্ষা করতে হয় না।

### Concurrency-র সমস্যা (নিয়ন্ত্রণ না থাকলে)

1. **Lost Update:** দুটি Transaction একই Data পড়ে আলাদাভাবে বদলায়; একজনের পরিবর্তন অন্যজনেরটা মুছে দেয়।

```text
সময়   T1 (জমা +1000)        T2 (উত্তোলন −500)      A-এর মান
 1     read(A) = 5000                                  5000
 2                            read(A) = 5000          5000
 3     A = 6000, write(A)                              6000
 4                            A = 4500, write(A)      4500   ← T1-এর +1000 হারিয়ে গেল!
 (সঠিক উত্তর হওয়া উচিত ছিল 5500)
```

2. **Dirty Read (Uncommitted Dependency):** T2 পড়ল T1-এর এমন পরিবর্তন, যা পরে ROLLBACK হলো। T2 একটি "ভুয়া" মান নিয়ে কাজ করল।
3. **Unrepeatable Read (Inconsistent Analysis):** একই Transaction একই Data দুবার পড়ে দুই রকম মান পেল, কারণ মাঝখানে অন্য Transaction বদলে দিয়েছে।
4. **Phantom Read:** একই শর্তে দুবার Query করে দ্বিতীয়বার নতুন "ভূতুড়ে" Row পাওয়া, কারণ মাঝে অন্য কেউ INSERT করেছে।

**Concurrency Control:** এই সমস্যাগুলো এড়িয়ে একসঙ্গে চলা Transaction-গুলোর Isolation ও Consistency নিশ্চিত করার পদ্ধতি।

## Schedule ও Serializability

**Schedule:** একাধিক Transaction-এর Operation-গুলো কোন ক্রমে চলবে তার তালিকা।

- **Serial Schedule:** একটি Transaction পুরো শেষ হলে তবে পরেরটি শুরু। সবসময় সঠিক, কিন্তু ধীর।
- **Non-serial (Concurrent) Schedule:** Operation-গুলো মিশ্রিতভাবে চলে।

**Serializability:** **একটি Concurrent Schedule-এর ফলাফল যদি কোনো একটি Serial Schedule-এর ফলাফলের সমান হয়, তাহলে Schedule-টি Serializable এবং সঠিক।**

- **Conflict Serializability:** দুটি Operation **Conflict** করে, যদি (১) আলাদা Transaction-এর হয়, (২) একই Data-র ওপর হয়, এবং (৩) অন্তত একটি **Write** হয়। Conflict না করা Operation-গুলোর জায়গা অদলবদল করে Serial Schedule-এ আনা গেলে Schedule-টি Conflict Serializable।
- **যাচাইয়ের পদ্ধতি: Precedence Graph।** প্রতিটি Transaction একটি Node। Ti-এর কোনো Operation Tj-এর Conflict-যুক্ত Operation-এর আগে এলে Ti → Tj Edge। **Graph-এ Cycle না থাকলে Schedule Conflict Serializable।**
- **View Serializability:** আরও বিস্তৃত সংজ্ঞা (প্রতিটি Read একই Write-এর মান পড়ে, আর শেষ Write একই)।

## Lock-based Protocol ও Data Locking

**Lock:** **একটি Data Item-এর ওপর একটি Transaction-এর অস্থায়ী নিয়ন্ত্রণ**, যাতে অন্য Transaction একই সময়ে বিরোধী কাজ করতে না পারে।

**Data Locking কেন প্রয়োজন:** Lost Update, Dirty Read, Unrepeatable Read-এর মতো সমস্যা ঠেকাতে, অর্থাৎ Isolation ও Consistency নিশ্চিত করতে।

**Lock-এর ধরন:**

- **Shared Lock (S, Read Lock):** শুধু পড়ার জন্য। একাধিক Transaction একসঙ্গে Shared Lock নিতে পারে।
- **Exclusive Lock (X, Write Lock):** পড়া ও লেখার জন্য। একবারে মাত্র একটি Transaction নিতে পারে।

**Lock Compatibility Matrix:**

| | S চাইছে | X চাইছে |
|---|---|---|
| **S ধরে আছে** | ✔ দেওয়া যাবে | ✘ অপেক্ষা |
| **X ধরে আছে** | ✘ অপেক্ষা | ✘ অপেক্ষা |

**Lock Granularity:** কত বড় অংশে Lock: পুরো Database, Table, Page বা Row। Row-level Lock-এ Concurrency বেশি, কিন্তু ব্যবস্থাপনা জটিল।

### Two-Phase Locking (2PL) Protocol

প্রতিটি Transaction দুটি ধাপে Lock নেয় ও ছাড়ে:

1. **Growing Phase:** শুধু Lock **নিতে** পারে, ছাড়তে পারে না।
2. **Shrinking Phase:** শুধু Lock **ছাড়তে** পারে, নতুন নিতে পারে না।

2PL **Conflict Serializability নিশ্চিত করে**, কিন্তু Deadlock ঠেকায় না।

- **Strict 2PL:** সব Exclusive Lock COMMIT/ABORT পর্যন্ত ধরে রাখে। Cascading Rollback এড়ায়।
- **Rigorous 2PL:** সব Lock (S ও X) COMMIT পর্যন্ত ধরে রাখে।

## Deadlock

**Deadlock:** **দুই বা ততোধিক Transaction এমন অবস্থায় আটকে যায় যে প্রত্যেকে অন্যের ধরে রাখা Lock-এর জন্য অনন্তকাল অপেক্ষা করে।**

![Deadlock: T1 অপেক্ষা করছে T2-এর জন্য, T2 অপেক্ষা করছে T1-এর জন্য](images/deadlock.png){width=5in}

> **উদাহরণ:** সরু রাস্তায় মুখোমুখি দুটি গাড়ি। কেউ পিছু না হটলে কেউই যেতে পারবে না।

**Deadlock-এর চারটি শর্ত (Coffman Conditions):** Mutual Exclusion, Hold and Wait, No Preemption, Circular Wait। চারটি একসঙ্গে থাকলেই Deadlock হয়।

**সমাধান:**

1. **Deadlock Prevention:** আগে থেকেই এমন নিয়ম, যাতে Deadlock না হয়। যেমন সব Lock একসঙ্গে নেওয়া, বা Timestamp-ভিত্তিক:
   - **Wait-Die:** পুরনো Transaction নতুনের জন্য অপেক্ষা করে; নতুনটি পুরনোর জন্য অপেক্ষা না করে "মরে" (Rollback)।
   - **Wound-Wait:** পুরনো Transaction নতুনটিকে "আহত" (Rollback) করে; নতুনটি পুরনোর জন্য অপেক্ষা করে।
2. **Deadlock Detection ও Recovery:** **Wait-for Graph** আঁকা হয়। Cycle পাওয়া গেলে Deadlock আছে। তখন একটি Transaction (Victim) বেছে Rollback করা হয়।
3. **Timeout:** নির্দিষ্ট সময়ের বেশি অপেক্ষা করলে Rollback।

## Timestamp-based Protocol

প্রতিটি Transaction শুরুতে একটি অনন্য **Timestamp** (সময়-চিহ্ন) পায়। পুরনো Transaction-কে অগ্রাধিকার দিয়ে Timestamp-এর ক্রমে Conflict-যুক্ত Operation চালানো হয়। ক্রম ভাঙলে Transaction Rollback হয়। Lock নেই, তাই **Deadlock হয় না**।

## Recovery System

**Failure-এর ধরন:** Transaction Failure (Logical Error, Deadlock), System Crash (বিদ্যুৎ, OS), Disk Failure।

**Log-based Recovery:** প্রতিটি পরিবর্তনের আগে একটি **Log**-এ লেখা হয়: `<T1, A, 5000, 4000>` (Transaction, Data, পুরনো মান, নতুন মান)। Crash-এর পরে:

- **Undo:** অসম্পূর্ণ (COMMIT হয়নি) Transaction-এর পরিবর্তন পুরনো মানে ফেরানো।
- **Redo:** COMMIT হওয়া Transaction-এর পরিবর্তন আবার প্রয়োগ।
- **Deferred Modification:** COMMIT-এর পরেই Database-এ লেখা (Undo লাগে না)।
- **Immediate Modification:** সঙ্গে সঙ্গে লেখা (Undo ও Redo দুটোই লাগে)।

**Checkpoint:** নির্দিষ্ট সময় পরপর সব পরিবর্তন Disk-এ লিখে Log-এ একটি চিহ্ন রাখা। Recovery-র সময় শুধু শেষ Checkpoint-এর পরের অংশ দেখতে হয়, তাই দ্রুত হয়।

**Shadow Paging:** পরিবর্তনের সময় পুরনো Page অক্ষত রেখে নতুন কপিতে কাজ করা। COMMIT-এ নতুনটি চালু হয়।

## মনে রাখার টিপস

- **ACID:** "**A**ll or nothing, **C**orrect, **I**ndependent, **D**urable।"
- Transaction State: **A → PC → C** (সফল পথ), **A → F → AB** (ব্যর্থ পথ)।
- **Shared = অনেকে পড়ে, Exclusive = একজন লেখে।**
- 2PL: আগে শুধু নাও (Growing), পরে শুধু ছাড়ো (Shrinking)।
- Wait-for Graph-এ **Cycle = Deadlock**; Precedence Graph-এ **Cycle নেই = Serializable**।

## অধ্যায় ৯: প্রশ্নোত্তর

**অতিসংক্ষিপ্ত প্রশ্ন ও উত্তর**

1. **Transaction কাকে বলে?** Database Operation-এর একটি যৌক্তিক একক, যা হয় পুরোপুরি হবে নয়তো একেবারেই না।
2. **Transaction-এর বৈশিষ্ট্যসমূহ কী কী?** ACID: Atomicity, Consistency, Isolation, Durability।
3. **Concurrency কাকে বলে?** একাধিক Transaction একই সময়ে চলা।
4. **Data Locking কেন প্রয়োজন?** Concurrent Transaction-এর সংঘাত ঠেকিয়ে Consistency রাখতে।
5. **Throughput কী?** নির্দিষ্ট সময়ে সম্পন্ন Transaction-এর সংখ্যা।
6. **Transaction State-গুলো কী কী?** Active, Partially Committed, Committed, Failed, Aborted।
7. **Concurrent Execution কী?** একাধিক Transaction-এর Operation মিশ্রিতভাবে চালানো।
8. **Deadlock কী?** Transaction-গুলোর পরস্পরের Lock-এর জন্য অনন্ত অপেক্ষা।
9. **COMMIT ও ROLLBACK-এর কাজ কী?** COMMIT পরিবর্তন স্থায়ী করে; ROLLBACK বাতিল করে।
10. **Serializability কী?** Concurrent Schedule-এর ফল কোনো Serial Schedule-এর সমান হওয়া।
11. **Checkpoint কী?** Log-এ রাখা চিহ্ন, যার আগের সব পরিবর্তন Disk-এ লেখা হয়ে গেছে।
12. **Two-Phase Locking-এর ধাপ কী কী?** Growing Phase ও Shrinking Phase।

**সংক্ষিপ্ত ও রচনামূলক প্রশ্ন**

1. Transaction-এর বৈশিষ্ট্যসমূহ (ACID) উদাহরণসহ বর্ণনা কর।
2. চিত্রসহ Transaction State Diagram ব্যাখ্যা কর।
3. Concurrent Execution-এর সুবিধা লেখ।
4. Concurrency Control না থাকলে কী কী সমস্যা হয়? উদাহরণসহ লেখ।
5. Shared ও Exclusive Lock-এর পার্থক্য লেখ।
6. Two-Phase Locking Protocol বর্ণনা কর।
7. Deadlock কী? Deadlock প্রতিরোধ ও শনাক্তকরণের পদ্ধতি লেখ।
8. Log-based Recovery ব্যাখ্যা কর।


# অধ্যায় ১০: ডাটাবেস সিস্টেম আর্কিটেকচার

> **এক নজরে:** Centralized Database System; Client-Server System (Two-tier ও Three-tier); Server System (Transaction Server ও Data Server); Server-based System-এর সুবিধা ও অসুবিধা; Parallel Database System (Speedup, Scaleup, Architecture); Distributed Database System (Homogeneous/Heterogeneous, Fragmentation, Replication, সুবিধা-অসুবিধা); Network Type ও Topology।

**আগের অধ্যায়ের সঙ্গে সম্পর্ক:** এতক্ষণ আমরা একটি DBMS-এর ভেতরের অংশ দেখেছি। এবার দেখব বড় প্রতিষ্ঠানে DBMS কীভাবে এক বা একাধিক Computer-এ সাজানো হয়, অর্থাৎ Architecture।

## Centralized Database System

**Centralized Database System:** **যে System-এ পুরো Database এবং DBMS একটি মাত্র Computer-এ থাকে** এবং সেখান থেকেই সব কাজ হয়। এটি হতে পারে একক ব্যবহারকারীর Personal Computer, অথবা একটি শক্তিশালী Computer যার সঙ্গে অনেক Terminal যুক্ত।

**দুই ধরন:**

- **Single-user System:** একজন ব্যবহারকারী (যেমন নিজের Laptop-এ MS Access)। Concurrency Control বা জটিল Recovery লাগে না।
- **Multi-user System:** একটি বড় Computer-এ অনেক ব্যবহারকারী Terminal দিয়ে যুক্ত।

**গঠন:** এক বা একাধিক CPU আর Device Controller একটি সাধারণ **Bus** দিয়ে **Shared Memory**-র সঙ্গে যুক্ত থাকে।

**সুবিধা:** সহজ ব্যবস্থাপনা; Data Integrity ও Security সহজ; Redundancy কম; খরচ কম।

**অসুবিধা:** Computer নষ্ট হলে পুরো System বন্ধ (Single Point of Failure); অনেক ব্যবহারকারী হলে ধীর; দূরের ব্যবহারকারীর জন্য অসুবিধা; Scalability কম।

## Client-Server System

**Client-Server System:** **যে Architecture-এ কাজ দুই ভাগে ভাগ হয়: Client (যে সেবা চায়, যেমন ব্যবহারকারীর Computer বা Mobile App) এবং Server (যে সেবা দেয়, যেখানে Database থাকে)**, আর দুটি Network দিয়ে যুক্ত থাকে।

![Two-tier ও Three-tier Client-Server Architecture](images/client_server.png){width=5.6in}

**Two-tier Architecture:** Client-এ Application ও User Interface থাকে। Client সরাসরি SQL পাঠায় Database Server-এ (যেমন ODBC/JDBC দিয়ে)। ছোট প্রতিষ্ঠানের জন্য উপযোগী।

**Three-tier Architecture:** মাঝখানে একটি **Application Server** থাকে, যেখানে Business Logic চলে। Client (Browser) শুধু Application Server-এর সঙ্গে কথা বলে, আর Application Server Database-এর সঙ্গে। Web Application এভাবে চলে (যেমন BTEB Result ওয়েবসাইট, Daraz)।

| বিষয় | Two-tier | Three-tier |
|---|---|---|
| স্তর | Client + DB Server | Client + Application Server + DB Server |
| Business Logic | Client-এ | Application Server-এ |
| নিরাপত্তা | কম (Client সরাসরি DB দেখে) | বেশি (DB সরাসরি উন্মুক্ত নয়) |
| Scalability | কম | বেশি |
| ব্যবহার | ছোট LAN Application | Web/Mobile Application |

**Client-Server Database-এর সুবিধা:**

1. কাজ ভাগ হয়, তাই Server-এর ওপর চাপ কমে।
2. Data কেন্দ্রীয়ভাবে থাকে, তাই Security ও Backup সহজ।
3. দূর থেকে (Network দিয়ে) ব্যবহার করা যায়।
4. Client ও Server আলাদাভাবে Upgrade করা যায় (Scalability)।
5. বিভিন্ন ধরনের Client (PC, Mobile) একই Server ব্যবহার করতে পারে।

## Server System

**Server System দুই ধরনের:**

1. **Transaction Server (Query Server):** Client Query বা Transaction পাঠায়, Server তা চালিয়ে শুধু **ফলাফল** ফেরত দেয়। যেমন MySQL, Oracle Server। সবচেয়ে প্রচলিত।
   - ভেতরের Process: Server Process, Lock Manager Process, Database Writer, Log Writer, Checkpoint Process, Process Monitor।
2. **Data Server:** Server Client-কে **Data (Page/Object)** পাঠায়, আর Client নিজে প্রক্রিয়া করে। দ্রুত Network ও শক্তিশালী Client-এ উপযোগী।

### Server-based Database System-এর সুবিধা ও অসুবিধা

| সুবিধা | অসুবিধা |
|---|---|
| কেন্দ্রীয় নিয়ন্ত্রণ, তাই Security ও Integrity ভালো | Server নষ্ট হলে সবার কাজ বন্ধ |
| Backup ও Recovery সহজ | Server ও লাইসেন্সের খরচ বেশি |
| একসঙ্গে অনেক ব্যবহারকারী | একসঙ্গে বেশি Request এলে Server-এ চাপ (Bottleneck) |
| Client-এ কম শক্তিশালী Computer চলে | Network-এর ওপর নির্ভরশীল |
| Data Sharing সহজ | দক্ষ Administrator লাগে |

## Parallel Database System

**Parallel Database System:** **যে System-এ অনেকগুলো CPU ও Disk একসঙ্গে (সমান্তরালে) কাজ করে**, যাতে বিশাল Database-এ Query দ্রুত চলে আর একসঙ্গে বেশি Transaction প্রক্রিয়া করা যায়।

**পরিমাপ:**

- **Throughput:** নির্দিষ্ট সময়ে কতগুলো কাজ শেষ হয়।
- **Response Time:** একটি কাজ শেষ হতে কত সময় লাগে।
- **Speedup:** একই কাজ, বেশি Hardware। যেমন Hardware দ্বিগুণ করলে সময় অর্ধেক হলে **Linear Speedup**।
- **Scaleup:** কাজ আর Hardware দুটোই বাড়ানো। যেমন দ্বিগুণ কাজে দ্বিগুণ Hardware দিলে সময় একই থাকলে **Linear Scaleup**।

### Parallel Database Architecture

![Parallel Database Architecture](images/parallel.png){width=6in}

| Architecture | বর্ণনা | সুবিধা | অসুবিধা |
|---|---|---|---|
| **Shared Memory** | সব Processor একটি সাধারণ Memory ভাগ করে | যোগাযোগ খুব দ্রুত | ৩২–৬৪টির বেশি Processor হলে Memory Bus-এ জট |
| **Shared Disk** | প্রতিটি Processor-এর নিজস্ব Memory, কিন্তু সব Disk সাধারণ | একটি Processor নষ্ট হলে অন্যটি কাজ নেয় (Fault tolerance) | Disk সংযোগে জট |
| **Shared Nothing** | প্রতিটি Node-এর নিজস্ব Processor, Memory ও Disk; Network দিয়ে যোগাযোগ | সবচেয়ে বেশি Scalable (শত শত Node) | যোগাযোগ খরচ বেশি |
| **Hierarchical** | উপরের তিনটির মিশ্রণ (যেমন Node-গুলো Shared Nothing, ভেতরে Shared Memory) | বড় System-এ ভারসাম্য | জটিল |

## Distributed Database System

**Distributed Database System:** **যে System-এ Database একাধিক Site (ভিন্ন ভৌগোলিক স্থানের Computer)-এ ছড়ানো থাকে, Site-গুলো Network দিয়ে যুক্ত থাকে, এবং ব্যবহারকারীর কাছে পুরোটা একটি Database হিসেবে মনে হয়।**

> **উদাহরণ:** একটি ব্যাংকের Dhaka, Chattogram, Rajshahi ও Sylhet শাখার নিজস্ব Database আছে, কিন্তু যেকোনো শাখা থেকে যেকোনো Account-এর তথ্য দেখা যায়।

![Distributed Database System](images/distributed.png){width=5in}

**Local Transaction:** শুধু নিজের Site-এর Data ব্যবহার করে। **Global Transaction:** একাধিক Site-এর Data ব্যবহার করে।

### Homogeneous ও Heterogeneous Distributed Database

| Homogeneous | Heterogeneous |
|---|---|
| সব Site-এ **একই DBMS Software** (যেমন সবাই MySQL) | বিভিন্ন Site-এ **বিভিন্ন DBMS** (MySQL, Oracle, SQL Server) |
| একই Schema | Schema আলাদা হতে পারে |
| একে অপরকে চেনে, সহযোগিতা করে | পরস্পরের সম্পর্কে কম জানে |
| ব্যবস্থাপনা সহজ | জটিল; অনুবাদ (Gateway) লাগে |

**Homogeneous Database (ব্যাখ্যা):** একটি প্রতিষ্ঠান শুরু থেকেই পরিকল্পনা করে সব শাখায় একই DBMS আর একই কাঠামো ব্যবহার করে। ফলে Query ও Transaction সহজে এক Site থেকে অন্য Site-এ চলে।

### Data সংরক্ষণের কৌশল: Replication ও Fragmentation

**Replication (প্রতিলিপি):** একই Data-র কপি একাধিক Site-এ রাখা।

- **সুবিধা:** Availability বাড়ে (এক Site নষ্ট হলেও অন্যটিতে পাওয়া যায়); Read দ্রুত।
- **অসুবিধা:** Update-এর সময় সব কপি হালনাগাদ করতে হয়।

**Fragmentation (খণ্ডায়ন):** Table ভেঙে বিভিন্ন Site-এ রাখা।

- **Horizontal Fragmentation:** Row অনুযায়ী ভাগ। যেমন Dhaka শাখার Account Dhaka-য়, Chattogram-এরগুলো Chattogram-এ। (σ দিয়ে)
- **Vertical Fragmentation:** Column অনুযায়ী ভাগ (প্রতিটি অংশে Primary Key থাকে)। যেমন ব্যক্তিগত তথ্য এক Site-এ, বেতনের তথ্য আরেক Site-এ। (π দিয়ে)

**Transparency:** ব্যবহারকারী জানেন না Data কোন Site-এ, কতগুলো কপি, বা কীভাবে ভাগ করা আছে (Location, Replication ও Fragmentation Transparency)।

**Two-Phase Commit (2PC) Protocol:** Global Transaction-এ সব Site একসঙ্গে COMMIT বা ABORT করে, তা নিশ্চিত করার পদ্ধতি। ধাপ ১ (Prepare): Coordinator সবাইকে জিজ্ঞেস করে "প্রস্তুত?"। ধাপ ২ (Commit): সবাই "হ্যাঁ" বললে COMMIT, একজনও "না" বললে ABORT।

### Distributed Database-এর সুবিধা ও অসুবিধা

**সুবিধা:**

1. **Data Sharing:** এক Site অন্য Site-এর Data ব্যবহার করতে পারে।
2. **Local Autonomy:** প্রতিটি Site নিজের Data নিজে নিয়ন্ত্রণ করে।
3. **Reliability ও Availability:** একটি Site নষ্ট হলেও বাকিগুলো চলে।
4. **দ্রুত Response:** Data ব্যবহারকারীর কাছাকাছি থাকে।
5. **Modular Growth:** নতুন শাখা খুললে নতুন Site যোগ করা সহজ।
6. **Parallel Processing:** একাধিক Site একসঙ্গে কাজ করে।

**অসুবিধা:**

1. Software ও ব্যবস্থাপনা জটিল।
2. খরচ বেশি (Network, একাধিক Server)।
3. Security নিশ্চিত করা কঠিন (অনেক জায়গায় Data)।
4. Concurrency Control ও Recovery জটিল।
5. Integrity রক্ষা কঠিন (Replication-এর কারণে)।

## Network Type ও Topology

**Network Type:**

- **LAN (Local Area Network):** ছোট এলাকা (একটি ভবন বা ক্যাম্পাস); দ্রুত; Parallel/Client-Server System-এ।
- **WAN (Wide Area Network):** বড় এলাকা (দেশ বা বিশ্বজুড়ে); তুলনামূলক ধীর; Distributed System-এ।

**Network Topology:** **Site-গুলো পরস্পরের সঙ্গে কীভাবে সংযুক্ত, তার জ্যামিতিক বিন্যাস।**

![Network Topology](images/topology.png){width=6in}

| Topology | গঠন | সুবিধা | অসুবিধা |
|---|---|---|---|
| **Fully Connected** | প্রতিটি Site সবার সঙ্গে সরাসরি যুক্ত | দ্রুত, খুব নির্ভরযোগ্য | খরচ সবচেয়ে বেশি |
| **Partially Connected** | কিছু Site-এর মধ্যে সরাসরি সংযোগ | খরচ কম | কিছু বার্তা ঘুরে যায় |
| **Tree (Hierarchical)** | গাছের মতো স্তরভিত্তিক | প্রতিষ্ঠানের কাঠামোর সঙ্গে মেলে | Parent নষ্ট হলে Child বিচ্ছিন্ন |
| **Star** | সব Site একটি কেন্দ্রীয় Site (Hub)-এর সঙ্গে যুক্ত | সহজ, খরচ কম | কেন্দ্র নষ্ট হলে সব বন্ধ |
| **Ring** | প্রতিটি Site ঠিক দুটি প্রতিবেশীর সঙ্গে যুক্ত, বৃত্তাকারে | সহজ গঠন | একটি Link নষ্ট হলে সমস্যা; বার্তা ঘুরে যায় |

## মনে রাখার টিপস

- **Centralized = এক Computer; Client-Server = সেবা চাওয়া/দেওয়া; Parallel = এক জায়গায় অনেক CPU; Distributed = অনেক জায়গায় অনেক Computer।**
- Speedup = একই কাজ দ্রুত; Scaleup = বেশি কাজ একই সময়ে।
- Horizontal Fragmentation = Row ভাগ (σ); Vertical Fragmentation = Column ভাগ (π)।

## অধ্যায় ১০: প্রশ্নোত্তর

**অতিসংক্ষিপ্ত প্রশ্ন ও উত্তর**

1. **Parallel Database System কী?** একাধিক CPU ও Disk একসঙ্গে কাজ করে এমন Database System।
2. **Centralized Database System কী?** পুরো Database ও DBMS একটি Computer-এ থাকে এমন System।
3. **Client-Server System কী?** Client সেবা চায়, Server সেবা দেয়, Network দিয়ে যুক্ত এমন Architecture।
4. **Distributed Database System কী?** একাধিক Site-এ ছড়ানো, Network দিয়ে যুক্ত, কিন্তু একক Database হিসেবে দেখায় এমন System।
5. **Topology কত প্রকার?** পাঁচ প্রকার: Fully Connected, Partially Connected, Tree, Star, Ring।
6. **Homogeneous Database কী?** সব Site-এ একই DBMS ও Schema।
7. **Replication কী?** একই Data-র কপি একাধিক Site-এ রাখা।
8. **Fragmentation কত প্রকার?** দুই প্রকার: Horizontal ও Vertical।
9. **Speedup কী?** Hardware বাড়িয়ে একই কাজ কম সময়ে করা।
10. **Three-tier Architecture-এর তিনটি স্তর কী?** Client, Application Server, Database Server।

**সংক্ষিপ্ত ও রচনামূলক প্রশ্ন**

6. Topology কত প্রকার ও কী কী? সংক্ষেপে লেখ।

## Experiment 16: Mini Project: Library Management System

**সমস্যা:** পলিটেকনিকের লাইব্রেরিতে বই, সদস্য (ছাত্র) আর বই ধার দেওয়ার হিসাব রাখতে হবে। একজন সদস্য অনেক বই নিতে পারেন; একটি বই বিভিন্ন সময়ে অনেকে নিতে পারেন (M:N)। ধার দেওয়ার তারিখ আর ফেরতের তারিখ রাখতে হবে। ১৪ দিনের বেশি রাখলে প্রতিদিন ৫ টাকা জরিমানা।

**E-R বিশ্লেষণ:**

- **Entity:** Book (book_id, title, author, category, copies), Member (member_id, name, roll, phone)।
- **Relationship:** Member **borrows** Book (M:N), যার Attribute: issue_date, return_date।
- **Table:** book, member, issue (M:N থেকে আলাদা Table, অধ্যায় ৩-এর নিয়ম ৬)।

```sql
CREATE TABLE book (
    book_id   INT PRIMARY KEY,
    title     VARCHAR(60) NOT NULL,
    author    VARCHAR(40),
    category  VARCHAR(20),
    copies    INT DEFAULT 1 CHECK (copies >= 0)
);

CREATE TABLE member (
    member_id INT PRIMARY KEY,
    name      VARCHAR(40) NOT NULL,
    roll      INT UNIQUE,
    phone     VARCHAR(15)
);

CREATE TABLE issue (
    issue_id    INT AUTO_INCREMENT PRIMARY KEY,
    member_id   INT NOT NULL,
    book_id     INT NOT NULL,
    issue_date  DATE NOT NULL,
    return_date DATE,                       -- NULL = এখনো ফেরত দেয়নি
    FOREIGN KEY (member_id) REFERENCES member(member_id),
    FOREIGN KEY (book_id)   REFERENCES book(book_id)
);
```
